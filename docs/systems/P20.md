  and before `validate()` (main file and backup alike), one pure step per version on a copy:
  `_migrate_1_to_2` adds `character.talents` `[]`, `character.ancestry_chosen` (true only for an
  ancestry other than `ancestry.neutral`), the `progress` block (`prologue_complete` from
  `slice.completed`, `world_entered` false, `levels_visited` the save's level, `tracked_quest` "")
  and the respawn's `checkpoint.position` / `yaw` from the level's world index. A damaged main file
  falls back to the (migrated) backup and the message leads with "Your last save was damaged; the
  previous one was loaded."; a file a newer build wrote is still refused and kept as
  `valley_1.schemaN.rejected.json`, and an older valid main file still becomes the backup
  (`SaveSlots.loads` migrates before it validates). Checkpoint documents now carry the respawn's
  position and yaw and the `progress` block (the tracked quest comes from `Quests.tracked_quest_id`
  once P27 adds it, and goes back into it on load). `CharacterState` normalises the new keys
  (unknown talent ids are dropped and reported like unknown abilities).
- **The campaign across levels** (`GameSession`; `Mode.VALLEY` is the campaign, `is_campaign()` its
  alias): `level_id` is the campaign level being played and the save's `level`;
  `current_level_id()`; checkpoints and saves work on every campaign level; Continue loads the save's
  level, and a level record this build lacks (a newer build's world) falls back to the Valley with a
  message ("The Old Kingdom is not in this build (level.world): you continue in the Valley."), at the
  Valley's return checkpoint once P26 builds it, else its start.
  - `travel_to(level, checkpoint, reason)` (reason `exit` | `fast_travel` | `debug` | `bot`): refused
    with a player-facing reason by the checkpoint blockers (an exit ignores aware enemies, fast
    travel ignores the open screen it is chosen on), for a destination checkpoint the index does not
    know, for one whose index `max_stage` is below the giant's stage ("The old paths here are too
    narrow for you now."), and for fast travel when the checkpoint is not visited (`visited.<id>`,
    set by GameSession when a checkpoint is reached) or its `requires_flags` do not hold. Otherwise it
    commits a checkpoint document whose level is the destination and whose respawn is the
    checkpoint (with its index position), emits `level_leaving` and reloads; the next level puts the
    giant there with the character, flags, inventory and world deltas intact.
  - `respawn_transform(id)`: the checkpoint node when loaded, else the world index entry.
    `respawn_checkpoint()`: the saved respawn unless a blocker refuses it (built in: its index
    `max_stage` below the stage; `register_respawn_blocker(Callable)` for P29 and P37), else the
    nearest visited unblocked checkpoint, else the start checkpoint, else the nearest unblocked one.
  - `level_entered(tick, level, reason)` once the level's `is_ready()` (when it has one) and
    `Audio.is_ready()` (when the autoload has one) hold, polled each frame (at most 1,200 frames);
    every load with a giant is entered (the sandbox's with reason `debug`). `entered_log` keeps them.
  - Shrines and waystones activate once per level visit (`activated_this_visit` /
    `mark_activated`), so a node made again in the same visit (a streamed chunk) gives no second free
    rest and no second checkpoint; a level load starts a new visit.
  - `--mode=world` (a New Game in `level.world` from `world_start`; `--continue` continues),
    `--start=<checkpoint>` (a New Game starts there, from the index when the node is not loaded),
    `start_new_world()`, `start_world_for_tests()`, `change_mode("world")`.
- **`LevelExit`** (`scripts/world/level_exit.gd`, group `level_exits`): an interaction that emits
  `travel_requested(to_level, to_checkpoint, "exit")` while its `requires_flags` hold, else shows its
  `locked_message`; `display_name` for the map and the index. Proven on two levels the test builds
  in code.
- **`WorldIndex`** (`scripts/world/world_index.gd`, a binary `.res` the builders write):
  checkpoints (position, yaw, display name, kind, fast travel, flags, district, `max_stage`),
  markers, areas, POIs, exits, encounters, props, districts, the road graph (widths, stage limits,
  `direct`), the region grid, the map picture and bounds; lookups by id (`position_of`,
  `display_name`, `checkpoint`, `max_stage_of`, `spawn_transform`, `region_at`, `district_at`,
  `nearest_road_node`, `route` - A* over the edges a stage may use), `for_level()` (cached) and
  `build_from_scene()` (what builders start from). `LevelRoot.index()`; `Quests.objective_position`
  falls back to it (moved with the level root) when a marker or target is not loaded.
- **The Valley's index** (`assets/world/index_valley.res`, 19,346 bytes, written by
  `tools/builders/valley.gd` from the built scene and the layout; a rebuild is byte-identical): the
  7 checkpoints (shrines named from their records, waystones from new layout fields: "Forest road
  waystone", "Ruins gate waystone", "Barrow gap waystone"; every `max_stage` 10 until P26 measures
  them), 59 markers, 14 areas, 32 props, 15 encounters, the 7 districts and 36 road nodes (the
  layout's road polylines, nodes within 0.5 m merged, loose road ends joined to the nearest other
  road within 15 m). `level_valley.json` names it.
- **Names, never ids**: the title's save line ("Saved game: level 7, stage 3, at the Grove Shrine,
  2026-11-06 14:02"; another level adds "in The Old Kingdom") and the checkpoint toast
  ("Checkpoint saved: Grove Shrine", "Game loaded: Forest road waystone") name the checkpoint from
  the index, else from the loaded shrine or waystone, and leave an unnamed one out
  (`GameSession.checkpoint_display_name`).
- **Quests in the campaign**: Quests run on every campaign level; the context gains `level_id`,
  `position`, `ancestry` and `ancestry_chosen`; `count`, `quest_done`, `level_is`, `ancestry_is` and
  `ancestry_chosen` are evaluated (the other new types below their packages' anchors); multi-marker
  stages (`markers`; the objective lists every marker and its known position, the position is the
  nearest to the giant); `xp_floor_level` (a stage awards max(its `xp`, the XP that reaches that
  level)); `waiting_text` in the objective; Quests listens to the six new tutorial events.
- **Dialogue**: `attribute_points` (unspent points to the giant's progression, else the session
  character; a HUD line), given once through the choice's `once_flag`; a choice whose conditions
  fail but that has `locked_text` is listed after the others, refused by `choose()` ("locked") and
  shown greyed with its reason by the dialogue screen ("3. Swear the peace (Return when you stand at
  stage 5)").
- **`world_start`** (`progression.default`): the Valley's worst guaranteed outcome - level 6 with
  1,050 XP (the XP budget's floor, force), stage 3 (`growth.03`), 15 unspent attribute points and 5
  talent points, the base club, the nine library abilities of level 6 in the force run's slots,
  the Ogre King's guaranteed loot (one tusk, one iron ingot) and the story and tutorial flags of a
  finished force run (`slice.completed`, `quest.village.outcome = force`, `faction.village.hostile`,

- **The title's skip-prologue choice**: when the saved game finished the prologue (its progress, or
  `slice.completed`) and `level.world`'s scene exists, New Game shows "Play the prologue" (focused)
  and "Skip to the Old Kingdom" (a New Game from `world_start`); both replace the save. Without the
  world the choice stays hidden (as in this build).

## Decisions and deviations

- **The visit set clears when a level loads** (`on_level_ready`), not on `level_entered` (§2.6):
  shrines near the spawn can activate before the level reports ready, and clearing later would let a
  reloaded chunk give a second free rest. Shrines and waystones read the set when they activate, not
  in `_ready` (a node made before the load's `on_level_ready` would otherwise inherit the previous
  visit).
- **`level_entered` for every load with a giant**: the sandbox's (and a test level's later loads)
  with reason `debug`, so a listener such as Audio never waits for an entry that does not come.
- **`GameSession.find_checkpoint` stays node-only**: the index fallback of §2.6 is in
  `respawn_transform` (and the snapshot's checkpoint position), which is where the node was used;
  a node of the level being left never places a travel's destination.
- **Fast travel waits for aware enemies** (only the screen blocker is ignored), as the checkpoint
  blockers do; an exit ignores them.
- **A refused travel is a HUD warning** (`hud_message`, kind `warn`) with the refusal's text;
  `last_travel_result` keeps it.
- **`visited.<checkpoint id>` is set by GameSession** whenever a checkpoint is reached in the
  campaign (shrines and waystones), the flag fast travel and the respawn search read.
- **Continue on a missing world** goes to the Valley's return checkpoint when the Valley's index has
  it (`valley.cp.kings_door`, P26), else the Valley's start checkpoint.
- **`world_start` leaves out the crown and the Valley's world deltas** (its inventory is the
  guaranteed loot the plan names, and the world is a different level); it includes the tutorial
  flags of the force run so the world never re-teaches the Valley's lessons.
- **A Valley boss kill keeps moving the respawn to Kingsfall** except on another campaign level
  record (a world boss keeps the respawn); test levels keep today's rule.
- **Files edited beyond §3.2's list**: `ui/screens/dialogue_screen.gd` (the locked choice as a
  greyed button with its reason - §2.12 asks for it) and `scripts/core/schemas/schema_util.gd` (the
  new condition shapes; without them every new condition type fails validation). Anchors were also
  put in P20's own six schema modules for the packages that ship their first records.
- **Tests updated for deliberately changed behaviour**: `tests/unit/test_save_slots.gd` (a "newer"
  save is now `SCHEMA_VERSION + 1`, not 2), `tests/unit/test_character_state.gd` (`talents` is a
  known key now; its unknown-key example is another key, and unknown talent ids are dropped and
  reported), `tests/integration/test_session_flow.gd` (the title's save line never shows the
  checkpoint id; the flow level has no index, so it names the character only).
- `WorldIndex.add_road` ignores a segment shorter than its merge distance (no stray node); a newer
  build's save is not called "damaged" in the recovery message.
