# P10a — Level framework: LevelRoot, area triggers, markers, EncounterDirector

Wave 4, lane B (beside P09). Branch `pkg/P10a`. Plan: `docs/plans/M2_M5_PLAN.md` §3.10, with the
contracts in §2.2 (groups, nav layers), §2.3 (ids and flags), §2.4 (`encounter_*`, `area_*`),
§2.5 (Sim PRE_ACTORS order 10), §2.7.3 (`begin_leash_return`, RETURN), §2.7.4 (LevelRoot,
AreaTrigger, LevelMarker, EncounterDirector), §2.8.1 (post-pass), §2.8.3 (`level`, `encounter`),
§2.12 (builders, test scenes) and decision 2.

## What was built

- **LevelRoot** (`scripts/world/level_root.gd`): the root of an encounter level. It names its
  `level` record and answers the lookups gameplay needs: markers, checkpoints, area triggers
  and patrol routes by id, the district at a point, the player, the navigation map and the
  region of each nav layer. Group `level_root` (ProjectileSystem parents projectiles there, P04's
  flee points snap to `nav_region()`, GameSession reads the start checkpoint of its record).
- **AreaTrigger** (`scripts/world/area_trigger.gd`): a named `Area3D` (no layer, mask actors)
  that reports the player walking in and out (`Events.area_entered` / `area_exited`) and keeps
  `player_inside` up to date; `once` reports the first visit only.
- **LevelMarker** (`scripts/world/level_marker.gd`): a named `Marker3D` of one kind (objective,
  cover, elevation, formation, safe, patrol, bot route) that joins its kind's group.
- **EncounterDirector** (`scripts/world/encounter_director.gd`): spawns a level's enemies from
  `encounter` records with their stable ids; activation and deactivation radii; the
  active-combatant budget (12); AI LOD tiers by distance; the leash; alert groups; kill
  persistence, corpses, clearing (flag and event once); `despawn()` and `force_activate()`.
- **Leash return** in `EnemyActor` / `EnemyBrain` (below `## @anchor P10a` only):
  `begin_leash_return()` and the RETURN state: run home ignoring the player, full health 6 s
  after the leash, AI back on at home.
- **Schemas** `level` and `encounter` (`scripts/core/schemas/{level,encounter}_schema.gd`) and
  the GameData post-pass checks (below `## @anchor P10a` in `game_data.gd`): a spawn entity id
  used by two encounters ("Duplicate spawn entity_id '…'"), a `definition` that is not an enemy
  or npc record, a district its level does not have.
- **The director test level**: `tools/builders/test_director.gd` → `scenes/test/director_test.tscn`
  (a 120 × 120 m floor in low walls, two pillars, an offline-baked human navmesh, markers, a
  patrol route, two triggers, the player and the director) and its data in `data/world/`
  (`level.director_test` and three encounters: wolves; soldiers with a commander and a patrol;
  a 14-member budget test).

## Public APIs

### LevelRoot (`class_name LevelRoot extends Node3D`, group `level_root`)

```gdscript
const GROUP := "level_root"
const NAV_REGION_NAMES := {1: "Human", 2: "Large", 4: "Giant", 8: "SmallGiant"}
@export var level_id := "level.valley"
func level_record() -> Dictionary          # the `level` record named by level_id, or {}
func marker(id: String) -> Node3D          # LevelMarker by marker_id
func checkpoint(id: String) -> Node3D      # CheckpointMarker / Waystone / shrine SpawnPoint by checkpoint_id
func area(id: String) -> AreaTrigger       # by area_id
func patrol_route(route_id: String) -> Node3D   # Markers/Patrol/<route_id.validate_node_name()>
func district_at(pos: Vector3) -> String   # the record's district rectangle (x, z) holding pos, or ""
func player() -> GiantPlayer               # the giant below this root (else any in the tree)
func nav_map() -> RID
func nav_region(layer: int) -> RID         # Navigation/<Human|Large|Giant|SmallGiant>, else any region on the layer
func spawn_parent() -> Node3D              # LevelRoot/Spawned (made when missing)
func director() -> EncounterDirector       # LevelRoot/EncounterDirector
func rebuild_lookups() -> void             # also done automatically when a lookup misses
```

- Lookups are built at `_ready` from the groups (`level_markers`, `checkpoints`,
  `area_triggers`), descendants of this root only, and rebuilt when an id is not found, so nodes
  added later are found.
- The scene layout it expects (the builders make it): `Navigation/{Human,Large,Giant,SmallGiant}`,
  `Markers/<Kind>/<marker>`, `Markers/Patrol/<route>/<n>`, `Triggers/<area>`, `Checkpoints`,
  `Spawns/PlayerSpawn`, `Spawned`, `Player`, `EncounterDirector`.
- **Patrol routes.** Node names cannot hold dots, so a route `valley.patrol.wolves_a` is the node
  `Markers/Patrol/valley_patrol_wolves_a` (`String.validate_node_name()`); a route node may also
  carry its id as meta `route_id` (the builder sets both). Its `Node3D` children are the points,
  in order.

### AreaTrigger (`class_name AreaTrigger extends Area3D`, group `area_triggers`)

```gdscript
@export var area_id := ""        # e.g. "valley.area.arena_engage"
@export var once := false        # report only the first visit (its entry and its exit)
var player_inside := false       # follows the player's body all the time (also after a `once` visit)
var entered_count := 0; var exited_count := 0
static func is_player_body(body: Node) -> bool   # group "player"
```

- `collision_layer` 0, `collision_mask` 2 (actors), `monitoring` on, `monitorable` off. Shapes are
  ordinary `CollisionShape3D` children.
- Events are emitted for the player only, with its entity id (`"player"`), **deferred to the end
  of the physics frame**: overlap callbacks run while the physics server flushes its queries,
  when a listener may not change physics state yet (P11a's arena gate closes on
  `arena_engage`). The tick is the tick that just ran.

### LevelMarker (`class_name LevelMarker extends Marker3D`, group `level_markers` + its kind's)

```gdscript
enum Kind { OBJECTIVE, COVER, ELEVATION, FORMATION, SAFE, PATROL, BOT_ROUTE }
const KIND_GROUPS := ["objective_markers", "ai_cover_points", "ai_elevation_points",
	"ai_formation_points", "safe_markers", "patrol_points", "bot_route_points"]
@export var marker_id := ""; @export var kind: Kind; @export var faction := ""
static func group_for(k: int) -> String
```

Changing `kind` in the tree moves the marker to the new group. P04's formation search reads
`ai_formation_points` and `faction`; tests may still put plain `Marker3D`s in these groups.

### EncounterDirector (`class_name EncounterDirector extends Node`, groups `encounter_director`, `debug_info_providers`)

```gdscript
signal member_spawned(encounter_id: String, entity_id: String, node: Node3D)   # after add_child
const HOOK_ORDER := 10                  # Sim PRE_ACTORS
const UNAWARE_DEACTIVATE_S := 10.0; const SPAWN_LIFT_M := 0.05
const DORMANT := "dormant"; const ACTIVE := "active"; const CLEARED := "cleared"
const UNSPAWNED := "unspawned"; const SPAWNED := "spawned"; const DEAD := "dead"; const DESPAWNED := "despawned"
var max_active_enemies; var near_m; var mid_m; var check_ticks; var corpse_free_s   # from the level record
var unaware_deactivate_s := 10.0        # tests may shorten it
var peak_active := 0                    # highest active_combatant_count() after an update
var level: LevelRoot
func spawned(entity_id: String) -> Node3D          # alive, or its corpse until freed; else null
func encounter_state(encounter_id: String) -> String
func active_combatant_count() -> int
func force_activate(encounter_id: String) -> void  # next update; ignores radius and flags, not "cleared"
func despawn(entity_id: String) -> void            # no kill; back at home on the next activation
func debug_lines() -> PackedStringArray
func update_now() -> void                          # a full update at once (tests, bot)
func encounter_ids() -> PackedStringArray; func members_of(encounter_id) -> PackedStringArray
func member_status(entity_id) -> String; func spawn_count(entity_id) -> int
func reload_encounters() -> void                   # re-read records and WorldState (frees all spawned)
func lod_tier_for(pos: Vector3, ppos: Vector3, engaged: bool) -> int
static func cleared_flag(encounter_id: String) -> String   # "encounter.<id without 'encounter.'>.cleared"
static func flags_allow(rec: Dictionary) -> bool
```

The update (Sim PRE_ACTORS, order 10; every `lod.check_ticks`, and at once after
`force_activate()`), encounters in id order:

| State | What happens |
| --- | --- |
| dormant | Activates when `flags_allow` (`requires_flags` all truthy, `forbids_flags` none), the player is within `activate_radius_m` of the centre (horizontal) and the budget has room (or a waiting member does not count toward it). It spawns, then emits `encounter_activated`. |
| active | Spawns members still waiting for room; leashes members beyond `leash_radius_m` from the centre (`begin_leash_return()`, `encounter_leashed`); sets LOD tiers; deactivates once the player is beyond `deactivate_radius_m` and no member has been aware for `unaware_deactivate_s` (10 s): living members are freed, not killed, and come back at home at full health on the next activation. |
| cleared | Never activates again (its flag survives reloads). Routed survivors are freed once the player is beyond the deactivate radius. |

- **Every tick:** alert groups share awareness. While a member is aware, each unaware one gets
  `brain.on_noise(tick, <aware one's last_known>, <its target>, true)` and wakes to tier 0. This
  keeps `last_aware_tick` (the deactivation grace) for every encounter.
- **Budget:** living, non-routed spawned members of encounters with `counts_toward_budget`
  whose definition is an `enemy` record (npc spawns never count; held bodies do). Members that do
  not fit wait (status `unspawned`) and spawn, in encounter-id and spawn order, as room frees up.
- **LOD:** tier 0 within `near_m` (40) of the player or while engaged (`brain.aware` or holding a
  token), tier 1 within `mid_m` (90), else tier 2. Held bodies (P07) keep their tier until
  released.
- **Kills:** a member with `persist_death` (default true) is recorded (`WorldState.record_killed`)
  and never spawns again; its corpse is freed `corpse_free_s` (6 s) later.
- **Clearing:** when every member is dead or routed: `WorldState.set_flag("encounter.<short
  id>.cleared", true)` and `encounter_cleared`, once. Members waiting or despawned keep it open.
- **Spawning**, before the actor enters the tree: the definition's `scene`; the CombatEntity's
  `definition_id` (so one scene can serve several definitions); `entity_id`, `ai_enabled`,
  `faction`, `encounter_id`, `persist_death`, `commander`, `loot_table`; `patrol_route` = the
  absolute path of `LevelRoot.patrol_route(patrol)`; `home_position`; position and yaw in level
  space (lifted 0.05 m); the LOD tier; then `LevelRoot/Spawned`. Properties are set only where the
  node has them, so non-EnemyActor scenes (P11b's civilians) spawn too. A member whose id is
  still registered with Sim (an older instance on its way out) waits for the next update.

### Leash return (`EnemyActor` / `EnemyBrain`, below `## @anchor P10a`)

```gdscript
# EnemyActor
const LEASH_HEAL_S := 6.0; const LEASH_ARRIVE_M := 1.5; const LEASH_HOOK_ORDER := 12
var leash_started_tick := -1; var leash_count := 0
func begin_leash_return() -> void      # drop the target and tokens, run home, full health 6 s later
func is_returning() -> bool
# EnemyBrain
func begin_return(tick: int) -> void   # RETURN: target, awareness, request, formation, flight dropped
func return_step(tick: int, home: Vector3) -> void   # run to home, face the way it runs, still no target
func end_return(tick: int, alive: bool) -> void      # IDLE at home (patrol resumes), DEAD if it died
```

- While returning, the actor's perception and decisions are paused (`ai_enabled` false; the
  previous value comes back at home) and a Sim PRE_ACTORS hook of its own (order 12, after the
  director) runs the return every tick: arrival within 1.5 m of `home_position` ends it, `LEASH_HEAL_S`
  after the leash it is healed (health through `CombatEntity.heal(…, "leash")`, so `Events.healed`
  shows it; full stamina; poise reset), and a death ends it with the brain DEAD.
- What it hears or is hit by on the way is forgotten at once: handlers connected after the base
  `_on_hit_taken` / `_on_any_ability_started` call `return_step`, so `aware` and `target_id` never
  survive a call (GameSession's checkpoint deferral never sees a returning unit as aware).
- The director does not leash a unit that is held (P07), fleeing, routed, dead or already
  returning, and never re-leashes it on the way.

## Decisions and deviations

1. **System doc name.** `docs/systems/P10a.md` (the task and §1.1 item 5); §3.10 names
   `P10a-level-framework.md`.
2. **RETURN is driven by the actor, with the AI paused.** `EnemyBrain.decide()` hands states it
   does not handle to the archetype's `_decide_engaged()` (WolfBrain turns any unknown state into
   APPROACH), and that function is outside the P10a anchor. So the leash pauses perception and
   decisions (`ai_enabled` false) and the actor's own PRE_ACTORS hook steps RETURN through the
   brain's `begin_return` / `return_step` / `end_return`. Every edit to the shared enemy files is
   below the P10a anchors (no hunk near P09's). An archetype that overrides `_custom_movement`
   must leave movement to `_steer` while `is_returning()`.
3. **Healing.** Full health 6 s after the leash, or on arrival when that comes first, so a unit
   is never home and hurt; stamina is refilled and poise reset at the same moment.
4. **Budget semantics.** The plan's "activate when … the budget allows" is read as: an encounter
   activates only when at least one waiting member can spawn now; members that do not fit wait
   and spawn in id order as room frees up (14 requested → 12 at once, the rest as others die).
   Routed members stop counting (they are out of the fight); held bodies count (P07).
5. **force_activate** ignores the radius and the flags (never a cleared encounter), takes effect at
   the next update (one tick, or `update_now()`), and on an active encounter is a re-activation:
   despawned members come back. Each activation restarts the 10 s deactivation grace.
6. **despawn** frees the node at the end of the frame (`call_deferred`): P11a calls it from an
   `area_entered` listener, and nodes must not leave physics during a query flush. The member is
   no longer listed and its AI is off at once.
7. **Routed members** count toward clearing. When an encounter that is not yet cleared
   deactivates, routed survivors are freed like the other living members and come back with it
   (decision 2's "living members … respawn at full health"); in a cleared encounter they are freed
   once the player is beyond the deactivate radius and never return.
8. **Flags are checked at activation only.** An active encounter does not deactivate when a flag
   changes (no slice flag is ever unset; the boss encounter is cleared by its own death).
9. **Spawn details.** Spawns are lifted 0.05 m (never inside the floor); the spawn sets the
   CombatEntity's `definition_id` from `definition`, so one scene can serve several definitions.
10. **Test data ships in `data/world/`.** The owned paths list no data, but the director spawns
    from records, and a test level with real records validates the schemas at every start and
    can be played: `--level=res://scenes/test/director_test.tscn`. `GameData` loads **one record
    per JSON file**, so the three encounters are three files.
11. **Area events are deferred** to the end of the physics frame (see AreaTrigger). `once` reports
    the first visit (entry and exit); `player_inside` keeps following the player.
12. **Navigation baked offline, without islands.** The builder bakes with
    `NavigationServer3D.bake_from_source_geometry_data` from the same box list as the collision
    (cell 0.3, agent radius 0.6 / height 2.0, plan §2.2). Recast rasterises surfaces, so the
    inside of a closed box stays walkable and becomes an unreachable island (and a top face is a
    second one); `region_get_closest_point` then happily returns points inside pillars. Obstacles
    are therefore added without their top face plus an `add_projected_obstruction` over their
    footprint (`carve` false, so the agent radius still applies). The result is one walkable level
    of 26 vertices and the scene regenerates byte-identically.
13. **Extra API** beyond §2.7.4: `LevelRoot.spawn_parent/director/rebuild_lookups/NAV_REGION_NAMES`,
    `LevelMarker.group_for/GROUP/KIND_GROUPS`, `AreaTrigger.entered_count/exited_count/is_player_body`,
    the director's `member_spawned`, `update_now`, `encounter_ids`, `members_of`, `member_status`,
    `spawn_count`, `reload_encounters`, `lod_tier_for`, `cleared_flag`, `flags_allow`,
    `peak_active`, `unaware_deactivate_s`, and `EnemyActor.is_returning/leash_count/leash_started_tick`.
14. **The leash test** lets the lured soldier run home for 6 s (it covers more than 12 m, takes a
    hit without reacting and is healed on time), then puts it a few metres from home to see the
    return end and the AI engage again: the whole 60 m run would add about 11 s of simulated
    time to a suite that is near its 45 s budget.

## Known gaps

- No Valley level yet (P10b): the framework is proven on the director test level only.
- No `npc` record type yet (P11b), so "npc spawns do not count" is tested through
  `counts_toward_budget: false`.

  headless `--level=res://scenes/test/director_test.tscn --autoplay=40` run exits 0 with no
  errors but fights nothing.

  deactivates; it is never teleported.
