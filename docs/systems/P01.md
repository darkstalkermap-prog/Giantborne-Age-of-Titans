# P01 — Core seams: validator registry, events, Sim phases, combat API, statuses, flags

Wave 0, lane A (beside P02). Branch `pkg/P01`. Plan sections: §2.4, §2.5, §2.6, §2.8.1–§2.8.3,
§2.9 (WorldState part), §2.11 and §3.1.

## What was built

- **Validator split with an optional schema registry.** `DataValidator` keeps record validation,
  reference checks and every shared enum. Each record type has a schema module in
  `scripts/core/schemas/<type>_schema.gd`. `SCHEMA_PATHS` declares a module path for every
  planned type, and only the files that exist are loaded. P01 wrote the modules for the nine
  existing types (moved code) plus `status_effect` and `progression`. All existing error strings
  are byte-identical.
- **Every planned enum value** (§2.8.1) is declared on `DataValidator`.
- **Events:** every signal of plan §2.4 is declared in `scripts/core/events.gd`, grouped by area,
  plus one anchor per later package (P02–P18).
- **Sim:** hook phases, named RNG streams, launch slots, the dead-shooter rule, and the
  built-in status pass.
- **Combat API:**
  - `CombatController` additions: level gating, `precheck`, `preview_reason`, `force_action`,
    the GRABBED and EXECUTING states, `phase_entered`, slows.
  - Statuses: `StatusDef` and `StatusSet`, the status folds on `Combatant`, and the status and
    heal entry points on `CombatEntity`.
  - `ResourcePool`: `rescale`, `snapshot`, `restore` and a fury-gain gate.
  - `PoiseMeter`: `recovery_mult` (the recovery punish) and `stagger_vs_larger_s`.
  - `DamageResolver` uses `armor_total` and `damage_taken_mult`. `HitEvent` gains its new fields.
  - `TargetingRules.player_may_target`.
- **GameData:** `get_status`, `records_of_type`, `override_record` and `restore_record` (which
  refresh the typed caches in place), `REQUIRED_RECORDS` merged from the modules, and a
  cross-record post-pass with anchors.
- **WorldState v2:** flags, killed and opened deltas, `record_damage`, `remove_item`, item events
  and v1 → v2 migration.
- **Input:** the actions `inventory`, `debug_grow`, `debug_shrink`, `debug_xp` and
  `debug_checkpoint`. The router emits the three debug edges in debug builds only.
- **Data:** `data/progression/progression_default.json`. **Project:** physics layer 6 is named
  `blockers`.

## Public APIs

### DataValidator (`scripts/core/data_validator.gd`)

`ATTACK_KINDS`, `HIT_SHAPES` (+ sector_pulse, projectile, grab, body_sweep), `ATTACK_CATEGORIES`,
`PROP_CATEGORIES`, `ARCHETYPES` (+ training), `WEAPON_FAMILIES` (+ tree, bow, staff, jaws,
natural), `ATTRIBUTES`, `CANCEL_INTO`, `PHASES`, `SIZE_POLICIES`, `INTERRUPT_POLICIES`,
`INTERACTION_PERMISSIONS`, `STATUS_STACKING`, `STATUS_MODIFIERS`, `STATUS_TAGS`, `MASS_CLASSES`,
`PROJECTILE_VISUALS`, `AIM_MODES`, `TELEGRAPH_SHAPES`, `GRAB_ATTACH`, `OUTMATCHED_BEHAVIORS`,
`NPC_ROLES`, `ITEM_CATEGORIES`, `DODGE_STYLES`, `CONDITION_TYPES`, `BOT_ACTIONS`,
`TUTORIAL_TRIGGERS`, `TUTORIAL_DISMISS`, `TUTORIAL_EVENTS` and `ID_REGEX`.

**Schema module contract.** Each module has no `class_name` and provides:

```gdscript
static func fields() -> Dictionary                              # type-specific field specs
static func semantic(d: Dictionary, ctx: String, out: Dictionary) -> void
static func required_ids() -> Dictionary                        # id -> type the code needs
```

**Adding a record type (P05, P10a, P11b, P12, P13).** Create
`scripts/core/schemas/<type>_schema.gd` at the path `SCHEMA_PATHS` already declares; do not edit
`data_validator.gd`. Ship the type's first records in the same package, because a record of a
type without a module fails validation. `test_schemas_v2` checks that `RECORD_TYPES` equals the
`*_schema.gd` files present.

**Adding fields to an existing type.** Each extendable module has its package anchors twice:
once in `fields()` and once in `semantic()`, with a blank line after each anchor. Insert directly
below your own anchor:
- in `fields()`: `f.merge({...})`;
- in `semantic()`: checks that use `d`, `ctx` and `out`.

### New record types

- **`status_effect`.** Fields: `hud_label`, `stacking` (required), `duration_s` (required),
  `tick_s`, `magnitude_key`, `default_magnitude`, `modifiers` (a map of `STATUS_MODIFIERS` keys to
  numbers ≥ 0), `tags` (`STATUS_TAGS`) and `hidden`. Semantic rules: a non-empty `magnitude_key`
  must be a `STATUS_MODIFIERS` key and must also appear in `modifiers`; `heal_per_tick` needs

  records; P03 ships the first ones.
- **`progression`.** Fields: `level_cap` (1–20), `xp_to_next` (ints), `attribute_points_per_level`,
  `talent_points_per_level`, `prototype_xp_label`, `death_reload_floor {health, stamina, essence}`,
  `ability_library` and `new_game {level, growth_profile, weapon, ancestry, slots, ultimate,
  known_abilities}`. Semantic rules: `xp_to_next` has `level_cap - 1` entries (19) and is
  non-decreasing; `new_game.slots` has 8 entries. Requires `progression.default`.

### GameData (autoload)

```gdscript
var REQUIRED_RECORDS: Dictionary            # now a var: merged from the modules (7 ids today)
func get_status(id) -> StatusDef
func records_of_type(type) -> Array          # raw dicts sorted by id (live; copy before writing)
func override_record(id, patch) -> Dictionary  # deep merge; returns the previous record
func restore_record(id, previous) -> void
```

- `override_record` merges dictionaries recursively and replaces arrays and scalars.
- It refreshes the cached `ActionDef` or `StatusDef` in place, using `ActionDef.fill(d)` and
  `StatusDef.fill(d)`. Holders of the object, such as `CombatController.library` or an active
  status instance, therefore see the change.
- An unknown id creates the record and returns `{}`. `restore_record(id, {})` then removes it.
- Restore several overrides of one id in reverse order.
- The patched record is not validated.
- Post-pass anchors: P09, P10a, P12 (in `_post_pass()`).

### Sim (autoload)

```gdscript
enum Hook { PRE_ACTORS, POST_ACTORS, POST_RESOLVE }
func add_hook(hook: int, owner: Object, callable: Callable, order: int = 100) -> void
func remove_hooks(owner: Object) -> void
func hook_count(hook: int) -> int
func rng_for(stream: String) -> RandomNumberGenerator
func reseed(seed_value: int) -> void         # rng and every stream (stream seed = seed ^ hash(name))
func request_launch_slot(target_id, holder_id, min_gap_ticks) -> bool
func last_launch_tick(target_id) -> int      # -1 = never
func clear_pending() -> void                 # hits, tokens and launch slots
```

- `step()` order: `tick += 1` → PRE_ACTORS hooks → actors in id order → POST_ACTORS hooks → hit
  resolution → status pass (`CombatEntity.tick_statuses(tick)` for every entity in id order) →
  POST_RESOLVE hooks. The actor order is rebuilt after the PRE_ACTORS hooks, so actors a director
  spawns there step on the same tick.
- **Hooks are called as `hook(tick: int)`.** `add_hook` refuses a callable that takes no
  argument, with an error.
- Hooks run in (phase, order, registration) order.
- A hook is dropped when its owner is freed. Owners are held through a `WeakRef`, so RefCounted
  owners are not kept alive. With `owner = null`, the callable's object is the owner.
- A hook added during a step first runs on the next tick.
- **Dead shooters.** A hit from a dead attacker is dropped unless it has
  `from_projectile = true` and the attacker died on an earlier tick
  (`attacker.died_tick != tick`).
- **RNG.** Crits keep using `Sim.rng`. New random consumers use `rng_for("<stream>")`.
  `test_sim_hooks_statuses` proves that stream draws leave the crit sequence and the 37 worked
  example unchanged.

### CombatController

New signal `phase_entered(action, instance_id, phase)`. It is emitted when the phase changes,
including the first phase on accept (after `action_started`). It is not emitted when the action
finishes.

New variables:
- `level := 99` (99 = gating off)
- `level_exempt := {}`
- `held_by := ""`
- `holding_id := ""`

`recovery_scale` already existed. CombatEntity now pushes Dexterity changes into it.

New functions:

```gdscript
func request(kind, params = {}) -> int        # params.precheck: Callable() -> String
func preview_reason(kind, params = {}) -> String   # "" accept, "busy" buffered, else the reason
func force_action(def: ActionDef) -> void
func enter_grabbed(holder_id: String) -> bool
func release_grabbed(reason: String, recovery_s: float = 0.6) -> void
func set_growth_stage(stage: int) -> void
```

- **`_evaluate` order.** dead → resolve → `unlock_stage` ("locked") → `unlock_level`
  ("level_locked"; skipped for ids in `level_exempt`) → cooldown → state ("busy", RETRY) →
  airborne → stamina → essence → fury → precheck.
- **Precheck.** It runs only when everything else would accept, and again when a buffered
  request is retried. A non-empty reason rejects with that reason and spends nothing.
- **`preview_reason`** goes through the same `_evaluate` as `request`, without side effects.
  Every RETRY reports "busy", including a dodge that waits for landing.
- **EXECUTING.** Actions with `hit_shape: "grab"` run in EXECUTING:
  - the timeline, move and rotate rules are the same as CASTING;
  - stamina regeneration pauses;
  - the action's own cancel rules apply;
  - it ends in LOCOMOTION.
- **GRABBED.**
  - The timeline does not advance.
  - Requests wait (RETRY "busy").
  - `apply_stagger` returns false.
  - The poise meter is locked.
  - `kill()` sets DEAD and clears `held_by`.
  - `enter_grabbed` works from LOCOMOTION, ATTACKING, CASTING, STAGGERED or BLOCKING. It
    interrupts the action without refund and clears the buffer and the stagger.
  - `release_grabbed` moves to STAGGERED for `recovery_s` (LOCOMOTION when it is ≤ 0). It emits
    the controller's `staggered` signal, but not `Events.staggered`.
- **`force_action(def)`.**
  - It finishes the current action as not interrupted (a light opens its chain window).
  - It clears the buffer and leaves STAGGERED, GRABBED or BLOCKING.
  - It then starts `def` without cost, cooldown or state checks.
  - It is ignored when dead.
- **Slows.** `move_speed_multiplier()` is multiplied by `combatant.move_mult()` in every state.

### Statuses (`StatusDef`, `StatusSet`)

`StatusDef.from_dict(d)` and `fill(d)` read:
- `duration_ticks` and `tick_ticks`;
- `stacking`;
- `magnitude_key` and `default_magnitude` (which defaults to the modifier's value);
- `modifiers`, `tags`, `hidden` and `hud_label`.

`StatusSet` has the §2.6.3 API plus `is_empty()`, `count()`, `active_ids()` and
`magnitude(id)`.

Stacking policies:
- `refresh_no_stack` keeps the magnitude and refreshes the duration.
- `strongest_wins` keeps the larger magnitude and refreshes the duration.
- `independent` adds a new instance.

Timing:
- A status applied at tick T with D ticks is active through T + D − 1 and is removed by the
  status pass on T + D.
- Periodic heals fall every `tick_ticks` after application, the last one on the expiry tick.
  Mend: 8 × 12.5 = 100 over 240 ticks. A refresh restarts the schedule.

How modifiers combine:
- `armor_flat` is summed;
- `slow_fraction` uses the strongest value, clamped to 0.9;
- `outgoing_damage_mult`, `outgoing_poise_mult`, `fury_gain_mult` and `damage_taken_mult` are
  multiplied.

Other behaviour:
- `hud_list` shows one row per id (the longest instance), sorted by id, without hidden statuses.
- `tick()` events also carry `"source"` (the caster).
- `remove()` and `clear()` emit `changed` but not `status_expired`.
- Statuses are not cleared on death; heals are skipped once dead.

### CombatEntity

```gdscript
var faction := ""          # from the actor's `faction` property in _ready
var died_tick := -1
func apply_status(status_id, magnitude = NAN, duration_s = -1.0, source_id = "") -> bool
func heal(amount: float, source_id: String) -> void
func tick_statuses(now: int) -> void
```

- `apply_status`:
  - An unknown id pushes an error. A dead entity or a status immunity (`status_immunities`
    against the status tags) returns false.
  - It emits `status_applied` with the duration actually applied.
- `heal` caps at the maximum and emits `healed` with the health actually gained (no event for 0).
- **On-hit effects.** `_apply_on_hit_effects` runs before `hit_resolved` is emitted.
  - On HIT it applies every entry of `hit.on_hit_statuses`; on BLOCKED, only the entries with
    `on_blocked`.
  - On HIT or BLOCKED, `morale_damage > 0` calls `actor.on_morale_delta(-morale, attacker_id)`.
  - Nothing is applied for a target the hit killed, or on EVADED, IMMUNE or GUARD_BROKEN.
- **Recovery punish.** Poise damage taken during the owner's attack RECOVERY phase is multiplied
  by `poise.recovery_mult`. `HitResult.poise_damage` reports the multiplied value.
- **Stagger against a much larger attacker.** A poise break by an attacker at least 2× this
  entity's height staggers for `stagger_vs_larger_s` when that is set.
- Attribute changes push the Dexterity `recovery_scale` to the controller.

### DamageResolver, HitEvent, TargetingRules

- Physical mitigation uses `armor_total()`. Both typed portions are multiplied by
  `damage_taken_mult()` before blocking and rounding. Without statuses every pinned number
  (37, 9, 66, 44) is unchanged.
- New `HitEvent` fields: `on_hit_statuses`, `morale_damage`, `from_projectile`, `projectile_id`
  and `area_effect`.
- `TargetingRules.player_may_target(e)` returns true for team ENEMY, and for team NEUTRAL with
  `faction == ""`. It returns false for team PLAYER, for NEUTRAL faction members and for null.

## Decisions and deviations

1. **Doc file name.** This file is `docs/systems/P01.md`, as the task and plan §1.1 item 5
   (`<package-id>.md`) say. Plan §3.1's owned-paths list names `P01-core-seams.md`.
2. **Anchor placement.** Plan §3.1 says each schema file "starts with" its anchor lines. The
   anchors sit inside `fields()` and `semantic()` instead (each package anchor appears in both),
   because code inserted at the top of a file could not reach those functions. Every §1.5 anchor
   exists as a whole line; P02's anchor test checks only that they are present.
3. **Hook signature `hook(tick: int)`.** The plan gives no hook signature.
4. **`xp_to_next` length rule.** It is checked as `level_cap - 1` entries rather than a literal 19
   (the same result for the cap of 20).
5. **`override_record` behaviour.** It refreshes caches in place, creates unknown ids, and
   removes them on `restore_record(id, {})`. This lets P02's `TestFixtures` inject in-memory
   records.
6. **`preview_reason` and RETRY.** It reports "busy" for every RETRY, as the contract says,
   including the airborne dodge.
7. **EXECUTING and cancels.** EXECUTING honours the action's cancel rules (like CASTING);
   previously EXECUTING was always "busy".
8. **`healed` amount.** It reports the health actually gained, and nothing is emitted at full
   health.
9. **Grab poise and recovery.** `enter_grabbed` locks the poise meter. `release_grabbed` with
   `recovery_s <= 0` goes straight to LOCOMOTION.
10. **`status_effect` modifier values are ≥ 0.** No slice status needs negative values. The
    status record type has no reference fields, so its tests have no bad-reference case.
    `progression` has no string enums, so its "bad enum" test uses an out-of-range `level_cap`.
11. **`WorldState.add_item` / `remove_item` parameters.** They take optional `source` / `reason`
    parameters to fill the event fields; the existing two-argument calls are unchanged. There
    are small helpers `count_of` and `is_opened`.
12. **Alias limitation.** `const V := DataValidator` fails to parse ("isn't a constant
    expression"), so modules spell `DataValidator.` out.
13. **Export check.** A Linux release export (binary tokens) was built to a scratch folder and
    run with `--autoplay=15`. The `.gdc` schema modules are found through their remaps, and data
    validates. Nothing from it is committed.
