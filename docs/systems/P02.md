# P02 — Actor seams: player components, enemy base, shared hits, interactables, HUD registry, test support, error counter

Wave 0, lane B (beside P01). Branch `pkg/P02`. Plan: `docs/plans/M2_M5_PLAN.md` §3.2, contracts §2.6.5, §2.7.1–2.7.4, §2.10.1, §2.13, §1.1, §1.5.

## What was built

A behaviour-preserving split of the three M1 hotspot actors, plus the seams later packages plug into.

- **GiantPlayer → components.** `scripts/actors/giant_player.gd` is now glue over a pre-declared component registry (`GiantPlayer.COMPONENTS`): `PlayerMotor` (sprint, facing, movement, dodge burst, knockback), `PlayerTargeting` (lock-on and soft targeting), `PlayerAttack` (weapon geometry, hit queries through `AttackRunner`) and `PlayerInteract` (the E key). The P05/P07/P08/P12 paths are listed and skipped until their files exist.
- **Enemy base.** `EnemyActor` (`scripts/actors/enemy_actor.gd`) holds everything generic from M1 `SoldierEnemy`; `EnemyBrain` (`scripts/ai/enemy_brain.gd`) holds the shared FSM, with the M1 melee behaviour as the default `_decide_engaged()`. `SoldierEnemy` is now only its brain and its frontal guard; `SoldierBrain` is an empty subclass that keeps the name and `SoldierBrain.AIState.*`.
- **One hit path.** `HitFactory` + `AttackContext` (`scripts/combat/`) build every HitEvent; `AttackRunner` (`scripts/actors/attack_runner.gd`) dispatches hit queries per `hit_shape` (`weapon_arc`, `cylinder_pulse`). `GiantPlayer._queue_hits` and `SoldierEnemy._run_hit_queries` are gone.
- **Interaction and checkpoints.** `Interactable` and `CheckpointMarker` (`scripts/world/`), `PlayerInteract`, and the HUD prompt widget `ui/hud/interact_prompt.gd` ("[E] Talk").
- **HUD widget registry.** `HudWidget`, `HudWidgets.WIDGETS` (all ten planned widget paths); `Hud._ready` creates the ones that exist. The HUD's "Stage N" label now refreshes on `Events.growth_changed`.
- **Debug tools.** The F3 `DebugPanel` lists any enemy (duck typed, nearest six, "+N more") and the lines of every node in group `debug_info_providers`. The autopilot targets any enemy.
- **Error counter.** `ErrorCounter` (`scripts/debug/error_counter.gd`) counts errors and warnings of tool runs; `AUTOPILOT_RESULT` gains `errors`, `warnings`, `error_samples` (first five), and the run exits with code 1 on any error.
- **Test support.** The runner runs `tests/slow` with `--slow`, calls `ResetHooks` around every test, and offers `TestRunner.take_logged_errors()`. `tests/support/`: `TestWait`, `TestSpawn`, `TestFixtures`, `ResetHooks`, `StubEnemy`, `AnchorsExpected` (the §1.5 table) and a probe for the hook tests.
- **Tools.** `tools/gd.sh` (per-worktree `user://`), `tools/check.sh` (the §1.1 sequence), `tools/run_tests.sh` through `gd.sh`; `.gitignore` gains `.userdata/`.

**Behaviour is unchanged.** All 1133 M1 checks pass unmodified, the obstacle route passes in both cameras, and the seeded `--autoplay=120` soak gives a byte-identical result on every M1 key (attacks 43, hits_resolved 37, rejections 37, soldier_kills 3, …). The new keys are `enemy_kills`, `errors`, `warnings` and `error_samples`.

## Public APIs

### GiantPlayer (`scripts/actors/giant_player.gd`)
Every M1 public name is kept: `router`, `controller`, `lock`, `entity`, `camera_rig`, `rig`, `body_shape`, `profile`, `weapon`, `record`, `growth_stage`, `stats`, `facing_yaw`, `sprinting`, `sprint_toggled`, `move_velocity`, `knockback_velocity`, `dodge_direction`, `prev_segment` (a property over the attack runner), `weapon_pivot`, `attack_origin`, `arm_length`, `weapon_length`, `weapon_radius`, `spawn_transform`, `last_intents`, `sprint_def`, group `player`, entity id `player`, the node paths, and `locked_entity()`, `weapon_segment_global()`, `get_defense_state()`, `apply_knockback()`, `on_entity_died()`, `flash()`, `get_rig_state()`, `get_debug_info()`.

New:

`sim_step` order (plan §2.7.1): consume → on_floor/block_held → `begin_tick` → (alive) components' `pre_actions` → meta edges (offered to components by `edge_priority`, unconsumed: default mapping — camera toggle, sprint toggle, lock/target edges) → hold-lock polled release → action edges (offered, unconsumed: `controller.request` as in M1) → `resume_held_block` → motor sprint, facing, movement → `attack.run_hit_queries` → components' `post_movement` → pools and poise → `targeting.maintain_lock` → out-of-world reset. Meta edges before action edges is the M1 order (a lock pressed in the same tick as a swing still aims the swing).

Character state: core keys are `loadout` (`{"slots": [8], "ultimate"}`), `known_abilities`, `level` (sets `controller.level` only when the controller has it and no progression component exists) and `resources` (last; `pools.restore` when it exists, otherwise assign + clamp + idle timers). Every other key is kept from the last apply and returned unchanged by capture, unless a component writes it in `capture_state`.

### PlayerComponent (`scripts/actors/player/player_component.gd`)

- `PlayerTargeting`: `locked_entity()`, `may_target(e)` (the single "may the player target this" rule; P03 switches it to `TargetingRules.player_may_target`), `eye()`, `is_visible()`, `gather_candidates()`, `soft_target_offset(base_yaw)`, `handle_lock_edge(e)`, `apply_hold_release(intents)`, `try_lock()`, `switch_target()`, `release_lock()`, `sync_lock()`, `maintain_lock()`, `on_any_entity_died()`, `apply_lock_profile()`. Anchors P03, P11a.
- `PlayerAttack`: `runner` (an `AttackRunner`, `emit_clank = true`), `refresh_geometry()` (profile + weapon; length and radius × `current_weapon_scale()`), `weapon_segment_global()`, `run_hit_queries()`.
- `PlayerInteract` (edge priority 50): refresh every 6 ticks (and on every E), candidates in `radius_m` + capsule radius and in front (dot ≥ 0.2, or closer than 1.5 m), plus component `interact_candidate()`s; best = lowest priority, then nearest, then id. `current_prompt()`, `current_candidate()`, `refresh()`, `use_candidate()`. After a use, `Events.interacted(tick, actor_id, interact_id)` is emitted when the signal exists (P01).

## Decisions and deviations from the plan
1. **System doc name.** §3.2 lists `docs/systems/P02-actor-seams.md`; the package task and §1.1 item 5 (`<package-id>.md`) say `docs/systems/P02.md`. This file is `P02.md`.
2. **`weapon_hit_radius()`** is a fifth duck-typed actor method for `AttackRunner` (the sweep radius must follow each actor's geometry cache; the plan's four methods do not carry it).
3. **`AttackContext.area_effect`** (a P02 field) is set for cylinder pulses and passed to `skip_candidate`. P02 never sets P01's `HitEvent.area_effect`; P03 copies the flag in `build` and fills in `skip_candidate`. `AttackContext.snapshot()` is added for in-flight projectiles.
4. **ResetHooks entries take an optional fourth element**: a failure message reported when the call returns a positive int. `close_all_static` uses it for "screen left open"; `restore_all` returns a count but carries no message, so restoring overrides is never a failure.
5. **`TestRunner` got a `class_name`** and a static `take_logged_errors()`, so a test that provokes errors on purpose (the error-counter test) can drain them. The runner's logger is a static.
6. **Anchor rows of other creators** (P01's events/schemas/game_data, P03's actor_rig/projectile_system) are checked only once the creator has landed, detected by a sentinel file (`scripts/core/schemas/schema_util.gd`, `scripts/world/projectile_system.gd`). The parser accepts `## @anchor P07` with any number of leading `#`, and ignores a trailing `:`/`,`.
7. **Extra GiantPlayer helpers**: `load_components`, `add_component`, `remove_component`, `components()`, `set_profile`, `set_weapon`, `known_abilities`, `is_action_edge`. `PlayerAttack.refresh_geometry()` already multiplies the weapon's length and radius by `current_weapon_scale()` (1.0 until growth profiles carry `weapon_scale`), so P05/P08 only change data and the scale rule.
8. **The M1 interact stub message is gone** ("Nothing to grab here yet…"): §2.7.4 says E with no candidate does nothing.
9. **EnemyActor details**: the `entity_id` default is `""`; after ready the actor mirrors the id its CombatEntity registered (the M1 soldier scene stores the id only on the CombatEntity, so placed soldiers keep `soldier_01`). `home_position` is the ready position unless it was set before. Movement is split into `_custom_movement` → `_steer` → shared knockback/gravity/`move_and_slide`. Soldiers now support `cylinder_pulse` actions too (M1 silently ignored them).
10. **Soldier hits** now carry `weak_point`, `pulse_id`, `attacker_growth_stage = 1`, and use Intellect for `magic` and `uses_weapon` for the weapon multiplier. No current hurtbox is a weak point and every soldier action is a melee weapon swing, so outcomes are identical.
11. **AUTOPILOT_RESULT** also gains `enemy_kills` (any `enemies` actor); `soldier_kills` is kept.
12. **Interact prompt device**: the widget tracks the last input device itself (P01 owns the router); P16 refines.
13. **DebugPanel** lists enemies nearest first, so the six shown are the relevant ones.
14. **A compile check of every script** (in `test_anchors.gd`) backs `check.sh`, because `--import` does not parse scripts: a broken file that nothing loads yet (a pre-declared registry path, for example) still fails the suite.
15. **Exports verified.** A pack exported with the release preset (`script_export_mode=2`: scripts become `.gdc` behind `.remap` files) runs the soak with 0 errors, so `ResourceLoader.exists(...gd)` + `load()` works for the component and widget registries in shipped builds.

## Known gaps
- `set_profile()` re-applies the capsule, controller stage, camera profile, geometry, lock range and rig pivot only. Height, camera framing, visual scale, clearance, resource rescaling, unlocks and `growth_changed` are P05's. `set_weapon()` does not rebuild the weapon mesh (P08).
- `PlayerInteract` has no line-of-sight test (the plan does not ask for one); candidates are horizontal-distance based.
- `Events.interacted` fires only once P01's signal exists; the test checks the payload when it does.
- No slow suite exists yet; the runner support is covered by `test_reset_hooks.test_runner_folders_and_discovery` and a manual `--slow` run.
- `ErrorCounter` starts with the autopilot (`configure`), so errors raised during engine start-up, before `main.gd` creates it, are not counted (invalid data stops `main.gd` before the autopilot exists; `check.sh` puts a time limit on every step).
