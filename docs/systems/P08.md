## What was built

- **Selective destruction in all three spec categories** (decision 23).
  - `BreakableProp` (`scripts/world/breakable_prop.gd`) now covers `breakable` and `structural`
    props: authored damage stages (the practice gate goes intact → cracked → broken), the damage of
    every hit saved and restored (a cracked gate reloads cracked; this also fixes the M1 limitation
    "fence partial damage is not persisted"), debris laid out from data, nav links that open when
    it breaks, a locked message for refused player hits, `protected`, XP for the player who breaks
    it, `on_destroyed_flags` and `open_when_flag` (`force_open`).
  - `CosmeticProp` (`scripts/world/cosmetic_prop.gd`): bushes and banners with no CombatEntity
    and no collision, never saved, that wobble on nearby pulses, sectors, roars and passing actors
    and flatten under a stage-2+ giant.
- **Weapons with fit stages and equipment** (decision 3).
  - `PlayerEquipment` (`scripts/actors/player/player_equipment.gd`, the `equipment` component):
    owned weapons, `equip_weapon` (LOCOMOTION only; stage and permission gates), the weapon's
    moveset in the loadout, the fit cap (`effective_weapon_scale`, which
    `GiantPlayer.current_weapon_scale()` now returns), the "too small" HUD warning, the weapon mesh,
    and the save keys `weapon` and `weapons_owned`.
  - `WeaponVisuals` (`scripts/presentation/weapon_visuals.gd`): the low-poly mesh of a weapon
    record, for the hand and for racks. `ActorRig.set_weapon_visual()` (anchor P08) puts it in the
    hand instead of the generated Club.
  - Seven weapon records (the club updated; sword, hammer, the three reinforced variants, the tree)
    and ten moveset actions; every light and heavy carries `BasicAttack`.
- **One-time world interactables**: `UprootTree` (the ancient oak gives the stage-3 tree weapon),
  `WeaponRack` and `ItemPickup`, each once per world id.
- **Scenes** (builder `tools/builders/world_props.gd`): `scenes/world/{gate_practice,
  gate_fortified, tree_small, ancient_oak, deadfall, cart_barricade, cairn, crate, weapon_rack,
  item_pickup, bush, banner}.tscn`.
- **The sandbox** gains a practice gate (`sandbox.gate_01`), a sword rack and a hammer rack, an
  ancient oak (`sandbox.oak_01`) near the shrine and two bushes.

## Public APIs

### BreakableProp (`class_name BreakableProp extends StaticBody3D`; group `breakables`)

```gdscript
@export var world_id := ""
const BLOCK_PREFIX := "Block"; const NAV_LINK_PREFIX := "NavLink"; const DEFAULT_DEBRIS_LENGTH_M := 8.0
const LOCKED_MESSAGE_GAP_TICKS := 180          # one locked message per 3 s
const PROTECTED_MESSAGE := "This cannot be broken."
const BREAKABLE_STAGES := [intact (1.0, Intact), broken (0.0, Broken, removes_collision, enables_nav_links)]
var entity: CombatEntity; var record: Dictionary
var destroyed: bool          # in its final state: broken, or opened by force_open
var opened: bool             # opened without breaking (no debris, loot, XP or flags)
var stages: Array; var stage_index: int
var last_rejection: String   # "", "destroyed", "protected", "category", "tags", "stage", "permission"
var locked_messages: int     # locked messages shown (tests)
static func stages_for(rec) -> Array                  # structural: damage_stages; else BREAKABLE_STAGES
static func stage_for_fraction(stages, frac) -> int   # the last stage whose at_or_below_frac >= frac
static func flag_truthy(v) -> bool
static func attacker_permissions(attacker_id) -> Array   # the attacker profile's interaction_permissions
static func is_player_id(entity_id) -> bool
static func debris_pieces(seed_id, count, length, layout) -> Array   # [{transform, velocity}], local
static func debris_piece_size(count, length, layout) -> Vector3
func is_structural() / stage_id() / health() / health_fraction() / open_flag() / locked_message()
func nav_links() -> Array[NavigationLink3D]; nav_links_enabled() -> bool; set_nav_links_enabled(on)
func has_collision() -> bool                           # any Block* shape still attached
func accepts_hit(hit) -> bool; rejection_reason(hit) -> String
func on_entity_died(killer_id)                         # the destruction (CombatEntity calls it)
func force_open(reason := "flag") -> bool              # Events.object_opened
```

- **Stages.** After every damaging hit the stage is `stage_for_fraction(health / max)`, never the
  last one (the last stage is entered only by the destruction at 0 health) and never backwards. A
  change shows that stage's visual child and hides the others, removes the `Block*` shapes when the
  stage `removes_collision` (immediately, as before, so a same-frame bake never sees them), enables
  the `NavLink*` links when it `enables_nav_links`, and for structural props emits
  `object_stage_changed(tick, world_id, index, stage_id)`. A blow that skips a stage emits only the
  stage it enters.
- **Destruction** (`on_entity_died`): the last stage (with its stage event), hurtboxes off,
  `record_damage(world_id, last, 0)`, `record_destroyed(world_id, last)`, debris, `object_destroyed`
  once, every `on_destroyed_flags` entry through `WorldState.try_set_flag`,
  `xp_award_requested(xp_reward, "prop:<world_id>")` when the killer is the player (team PLAYER),
  then the loot once per world id (`try_award_loot`, `add_item(..., "loot")`, `loot_awarded`).
- **Gating** (`accepts_hit`, in this order): destroyed, `protected`, category not in
  `accepted_attack_categories`, a `required_tags` tag missing on the hit, `attacker_growth_stage <
  min_growth_stage`, the attacker's profile lacks `requires_permission`. A refused hit is
  CombatEntity's IMMUNE with notes `not_permitted`; `last_rejection` names the reason. A refused
  hit by the player posts the record's `locked_message` (`PROTECTED_MESSAGE` for a protected prop
  without one) as a `warn` HUD message, at most once every 180 ticks.
- **Persistence.** Every damaging hit calls `WorldState.record_damage(world_id, stage, health)`.
  `_ready` restores silently (no events, debris, loot or XP): `destroyed` or `opened` deltas give
  the final state (visual, no collision, links on, hurtboxes off, dead); a `health` delta gives the
  health and the saved stage.
- **`open_when_flag`** opens the prop when the flag becomes truthy (`flag_changed`) or is set at
  `_ready`: `force_open` puts it in its final state without debris, loot, XP or flags, records the
  delta `opened` and emits `object_opened(tick, world_id, reason)`. A broken prop no longer opens.
- **Debris.** `debris_layout` `line` spreads `debris_count` pieces along local X over
  `debris_length_m` (default 8; fences, gates, felled trees), `pile` heaps them within a quarter of
  that length (cairns, crates, the Deadfall). Deterministic per world id (a private RNG). Piece size:
  planks for lines (an 8 m, 8-piece fence keeps the M1 plank, 0.16 × 0.16 × 1.5 m), chunks for
  piles.

### DebrisPool

`spawn(transforms, velocities, piece_size := Vector3.ZERO)`: every piece of one spawn gets that box
size (ZERO = `PLANK_SIZE`); each pooled body owns its box shape, which is resized (never
node-scaled, Jolt), and its mesh is scaled to match. `active_sizes()` for tests. Unchanged
otherwise (40 pieces, 5 s, 1 s off screen).

### CosmeticProp (`class_name CosmeticProp extends Node3D`; group `cosmetic_props`)

```gdscript
@export var prop_id := "prop.bush"; @export var react_radius_m := -1.0   # < 0: the record's
const CHECK_TICKS := 12; const FLATTEN_S := 4.0; const FLATTEN_STAGE := 2; const PULSE_MARGIN_M := 0.4
var react_count := 0; var flattened := false; var last_react_source := Vector3.INF
func react(source: Vector3, strength: float) -> void   # >= 1 flattens for 4 s, else wobbles
static func flattens(actor) -> bool                     # a giant (group player) of stage >= 2
static func actor_radius(actor) -> float                # profile / record capsule_radius_m (0.4)
```

It reacts to `area_pulse` whose radius (+0.4 m) reaches it, to `ability_effect` `sector` (inside
the radius and the arc) and `roar`, and to actors of the groups `player`, `enemies` and `npcs`
coming within `react_radius_m` + their capsule radius, checked every 12 ticks from a Sim
POST_RESOLVE hook (order 220, phase-shifted per prop); an actor counts once per pass. At most one
reaction per tick (a roar's pulse and its roar effect count once). The wobble and the flatten are
tweens on the `Visual` child; nothing is saved and nothing touches combat.

### PlayerEquipment (`class_name PlayerEquipment extends PlayerComponent`; `player.equipment`)

```gdscript
const STATE_WEAPON := "weapon"; const STATE_OWNED := "weapons_owned"
const HAND_OFFSET := Vector3(0, 0, -1.5)
const FIT_WARNING := "Your %s is too small for you now. Reforge it at a forge to make it fit."
const REASONS := ["unknown", "not_owned", "busy", "stage", "permission"]
var visual: Node3D; var last_result: Dictionary
func equip_weapon(id) -> Dictionary          # {ok, reason, message}
func can_equip(id) -> Dictionary             # the same checks, changes nothing
func grant_weapon(id, equip := false) -> Dictionary   # owned once; with equip: equip_weapon's result
func owned() -> PackedStringArray; owns(id) -> bool
func weapon_id() -> String; weapon_name(id := "") -> String
func effective_weapon_scale() -> float       # GiantPlayer.current_weapon_scale() returns this
func fit_stage() -> int                      # min(stage, fit_max_stage); the stage for fixed-size ones
func is_too_small() -> bool                  # stage > fit_max_stage (scaling weapons only)
func weapon_label(id) -> String              # "Oak Club (too small)" for the inventory (P12)
func visual_length() -> float                # the mesh's grip-to-tip length in world metres
static func too_small_at(rec, stage) -> bool
static func scale_for(rec, stage, profile) -> float
static func upgrade_problems(records) -> PackedStringArray   # the cross-record upgrade fit rule
```

- **Equipping** needs LOCOMOTION (never mid-swing: the sweep's length must not change during
  ACTIVE), ownership, `required_stage` and `required_permission` (the tree: stage 3 and
  `tree_weapon`). It calls `player.set_weapon` (every component's `on_weapon_changed`;
  PlayerAttack re-reads the geometry), puts the weapon's `light_chain` / `heavy` into
  `controller.loadout` (else the player record's), adds their chains to the library, forgets an
  open light chain, rebuilds the mesh, emits `weapon_equipped` and `loadout_changed`, and posts
  "Equipped: <name>" or the fit warning.
- **Fit.** `effective_weapon_scale()` is the `weapon_scale` of the growth profile of
  `min(stage, fit_max_stage)`; 1.0 for `scales_with_growth: false` (the tree keeps its real 7.5 m).
  Growth past the fit stage queues the HUD warning for the next tick (`post_movement`); a restore
  (`apply_state`, which runs after growth's) cancels it, so loading a save is silent.
- **The mesh** (`WeaponVisuals.build`) goes under `Visual/Body/ShoulderR` as `Weapon` at the hand
  and hides the generated `Club`. The body is scaled k, so the node is scaled
  `effective_weapon_scale / k` and the mesh is exactly as long as the sweep. The tree's canopy is
  on render layer 2 (hidden in first person) and the tree sets the rig's `idle_arm_pose` to
  `WeaponVisuals.TREE_IDLE_POSE` (raised to the right, clear of the view centre); other weapons
  get the rig's own pose back.
- **Save keys**: `weapon` (the equipped id) and `weapons_owned` (ids, in the order they were
  gained). `apply_state` equips silently (no events, no warning, no busy check) after growth.

### WeaponVisuals (`class_name WeaponVisuals`, static)

`build(rec) -> Node3D` ("Weapon"; grip at the origin, tip at −Z `length_m`), `shape_of(rec)`,
`is_reinforced(rec)` (id ends in `_reinforced`: iron bands or a ridge), `idle_pose(rec)`
(`Vector2.INF` = the rig's), `local_length(node)`, `world_length(node)`, `material(name)`,
`TREE_IDLE_POSE = (24, 30)`. Shapes: club (the M1 cylinder), sword (pommel, grip, guard, blade),
hammer (shaft, wide iron head), tree (trunk, roots, branches, canopy on layer 2), else a staff.

### ActorRig (anchor P08)

`var weapon_visual: Node3D`; `set_weapon_visual(node, hand_offset := (0, 0, -1.5))`: removes the
previous weapon mesh (and its materials from the flash and tint list), hides the generated `Club`
(null shows it again), adds the node under the weapon arm and registers its materials.

### Interactables (`Interactable` subclasses; exports as in §2.7.4)

- `UprootTree`: `world_id`, `prop_id` (`prop.ancient_oak`), `weapon_id` (`weapon.tree_oak`; `""`
  = the record's `uproot_weapon`). `can_interact` needs the record's `requires_permission`
  (`tree_weapon`) and LOCOMOTION; `blocked_reason` is the record's locked message ("Too small to
  uproot this oak (stage 3).") or "Finish your attack first.". `interact`:
  `equipment.grant_weapon(weapon_id, true)`, `record_destroyed(world_id)`, `try_set_flag
  ("world.tree_weapon_taken")`, a HUD line, the oak hidden with its `Trunk` collision off. A
  destroyed delta loads it uprooted. `uprooted`, `record()`, `has_permission(player)`.
- `WeaponRack`: `world_id`, `weapon_id`. Builds the weapon's mesh upright under `Display`.
  `interact` (LOCOMOTION) grants and equips it once (delta `taken`) and empties the rack.
  `taken`, `display_weapon`, `weapon_name()`.
- `ItemPickup`: `world_id`, `item_id`, `count`, `set_flag`. `interact` adds the items
  (`add_item(..., "pickup")`), emits `loot_awarded` (the HUD's "+N"), sets the flag (first write
  wins), records `taken` and hides `Visual`. Static `is_taken(world_id)` / `record_taken(world_id)`
  (the delta key `taken`; WeaponRack uses them too).

### Others

- `GiantPlayer.current_weapon_scale()` returns `equipment.effective_weapon_scale()` when the
  equipment component exists (the one-line hook of plan §3.8).
- `PlayerEquipment.upgrade_problems(GameData.records)`: every `upgrade.to` weapon fits at least as
  high as its source.

## Decisions and deviations

1. **Doc name.** `docs/systems/P08.md` (the task and §1.1 item 5); §3.8's owned paths name
   `P08-world-weapons.md`.
2. **`protected` reports IMMUNE `not_permitted`, not `protected`.** The notes of a refused hit are
   CombatEntity's (P01's file, not P08's this wave), which writes `not_permitted` for every
   `accepts_hit` refusal. `BreakableProp.last_rejection` is `protected` and the message is shown.
   P11a (the next owner of `combat_entity.gd`) could copy `last_rejection` into the notes.
3. **The fortified gate has two stages** (intact → breached), not one: the schema requires a
   structural prop's last stage at 0.0 with `removes_collision`, and a one-stage prop could not be
   both. The breach is unreachable in the slice (stage 4 and `gate_breach`).
4. **The practice gate drops 2 wood scraps.** §2.8.4's record has no loot, but §3.8's tests ask that
   its destruction awards "XP and loot once".
5. **The upgrade fit rule is checked outside the validator.** "An `upgrade.to` weapon fits at least
   as high as its source" spans two records, a schema module's `semantic()` sees one, and the
   GameData post-pass has no P08 anchor. `PlayerEquipment.upgrade_problems(records)` implements it;
   `test_weapons` runs it on the shipped data; P12 (forge, post-pass anchor) may call it there.
6. **Moveset timings in whole ticks.** §4.7's sword 0.16 / 0.12 / 0.24 s and maul 0.28 / 0.15 /
   0.38 s are not whole 1/60 s ticks (the validator would warn); they are 10 / 7 / 14 and 17 / 9 / 23
   ticks (0.1667 / 0.1167 / 0.2333 and 0.2833 / 0.15 / 0.3833 s). The arcs were searched with a
   geometric model of the sweep and confirmed in the engine: the sword's and the maul's lights land
   on a soldier 0.6 × melee reach ahead at every stage they fit (stage 3 reforged), and the sword's
   thrust lands on a soldier at a stage-3 giant's feet with the unreforged (stage-2 size) sword.
   They get the stage's base arc tilt; no growth profile was edited.
7. **The tree is a mid-range weapon.** Its sweeps (pitch −22 → −32 → −22, −12 more at stage 3)
   hit soldiers from about 2.6 to 6 m ahead and farther to the right, not at the giant's feet; the
   smash ends 1.7 m into the ground at its tip. The tree's mesh would hang 10 m into the ground at
   the M1 rest pose, so the tree is carried raised to the right (`TREE_IDLE_POSE`), which also keeps
   the trunk right of the first-person view centre.
8. **The weapon mesh is always the equipment's.** The generated `Club` stays in `giant.tscn`
   (hidden at start-up) so the scene is unchanged; the `Weapon` node replaces it for every weapon,
   the club included.
9. **`grant_weapon` returns a Dictionary** (equip_weapon's result with `equip`), a superset of the
   plan's `void`.
10. **Too-small warning timing.** On growth the warning is posted one tick later (from
    `post_movement`), so a save restore, which applies growth and then the weapon in one call, can
    cancel it. Equipping an outgrown weapon warns at once.
11. **`WeaponVisuals` is a new file** (`scripts/presentation/weapon_visuals.gd`) outside §3.8's owned
    list: the racks and the hand share it. No other package uses the path.
12. **One-time interactable deltas.** WorldState (P01) has no "taken" helper; `ItemPickup`'s static
    `is_taken` / `record_taken` write the `taken` key into `WorldState.deltas`, which saves and loads
    like the other delta keys. The oak uses `record_destroyed` as planned.
13. **Cosmetic records keep the prop schema's required fields** (`health`, `accepted_attack_categories`;
    `health 1`, `[]`): P01's base fields are required for every category.
14. **Debris sizes from data.** `DebrisPool.spawn` takes a piece size (the plan's fields are only
