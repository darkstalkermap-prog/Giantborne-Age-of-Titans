# P06 — Game session, saves, checkpoints, waystones, title and death flow

Wave 2, lane B (beside P05). Branch `pkg/P06`. Plan: `docs/plans/M2_M5_PLAN.md` §3.6, with the
contracts in §2.4 (checkpoint, reload and mode events), §2.7.4 (Waystone), §2.9 (session,
character state, save schema, checkpoint rules), §2.10.1 (checkpoint toast), §2.10.2 (title
screen), §2.11 (F9), §2.13 (`reset_for_tests`), and decisions 13, 14, 15 and 22.

## What was built

- **GameSession** (`scripts/core/game_session.gd`, autoload after WorldState): the mode (title,
  sandbox, Valley), the command-line options, the live character state, the last checkpoint
  document, and the flows New Game, Continue, sandbox, quit to title, checkpoint, death and
  reload. Every mode change and reload is a reload of `main.tscn`; `main.gd` builds what the
  mode asks for and calls `GameSession.on_level_ready(level, player)`.
- **Checkpoints**: the §2.9 triggers (shrine first activation, Rest, the shrine screen,
  waystones, growth at a shrine, the boss, `quest.main` stages), one pending request drained
  from a Sim POST_RESOLVE hook (order 200), the deferral rules (dead, grabbed, executing,
  holding, a modal screen, an aware enemy within 40 m), respawn points, and the death-reload
  floor (health 60 %, stamina 100 %, essence 50 %, fury 0).
- **SaveSlots** (`scripts/core/save_slots.gd`): the one slot `user://saves/valley_1.json` over
  SaveIO, with validation, backup recovery, a kept copy of newer-version files, and unknown ids
  dropped with a message.
- **CharacterState** (`scripts/progression/character_state.gd`): the new-game character,
  int casts after JSON, defaults, unknown-id drops and validation.
- **Waystone** (`scripts/world/waystone.gd`): a checkpoint marker reached by walking within its
  radius once its flags are set; once per load.
- **Title screen** (`ui/screens/title_screen.gd`): New Game, Continue, Sandbox, Settings,
  Controls, Quit. Without `--mode` the game (and the web play link) now opens here.
- **main.gd**: title or level by mode, a one-frame "Loading..." label, `on_level_ready`, the
  death confirm by mode (Enter / pad A), F9, and resets routed through GameSession.
- **Pause menu**: Resume, Load last checkpoint (where checkpoints exist), Restart sandbox
  (outside the Valley), Quit to title, Quit to desktop (not on the web).
- **HUD**: the death hint by mode; the checkpoint toast widget (`ui/hud/checkpoint_toast.gd`).
- **Flow test level** (`tools/builders/test_levels.gd` → `scenes/test/flow_test_level.tscn`,
  root script `scripts/world/flow_test_level.gd`): floor, `test.cp_a` (start), `test.cp_b`,
  the waystone `test.cp_way` (needs `test.way_open`), the fence `test.flow_fence`, a stub-enemy
  spawn point, the Player and a debris pool. Its root sets `GameSession.test_checkpoints` while
  it is in the tree.
- `project.godot`: the GameSession autoload and version `0.2.0-m3`.

The sandbox is unchanged when started with tool flags: the seeded `--autoplay=120` soak gives
the same result as the wave-1 tip on every gameplay key (attacks 44, hits_resolved 34,
rejections 45, enemy_kills 5, fence_breaks 1, max_debris 8, loot_awards 1, resets 1, …); only
the autopilot's `frames` counter differs (7201 vs 7199).

- **Listens to** `checkpoint_reached`, `shrine_activated`, `shrine_rested`,
  `ui_screen_requested` (screen `shrine`), `growth_changed`, `boss_defeated`,
  `quest_stage_changed`, `reload_checkpoint_requested`, `mode_change_requested`,
  `entity_died` (death count). **Emits** `checkpoint_saved(tick, respawn_id, ok, message)` for
  every committed checkpoint (message `""` = written, `"saving is off"`, `"kept in memory"`, or
  the write error) and `checkpoint_loaded(tick, respawn_id, source)` after a restore (`continue`,
  `death`, `debug`, `menu`). A write failure also posts a `hud_message` warning; play continues
  with the checkpoint in memory.
- **Respawn points.** `checkpoint_reached` → that marker; `shrine_activated` / `shrine_rested`
  → the shrine (its id when a checkpoint marker has it, else the node in group `shrines` whose
  `shrine_id` or `world_id` matches, else unchanged); the shrine screen → the requesting
  shrine's `world_id` (or its SpawnPoint's id); `growth_changed` for the player → the nearest
  shrine within 25 m (none near: no checkpoint); `boss_defeated` → `valley.shrine.kingsfall`;
  `quest_stage_changed("quest.main")` → unchanged.
- **Pending request.** One at a time: a later request replaces the reason and, when it names a
  respawn, the respawn (a waystone reached while an enemy was aware is not lost to a later quest
  stage). Retried every tick in POST_RESOLVE while checkpoints are enabled. The shrine screen's
  checkpoint is taken at once in the signal handler, before the ScreenStack opens the screen.
- **Writes.** Only `persist and is_valley()` writes the slot. A test level in the sandbox mode
  keeps checkpoints in memory, so it can never overwrite the player's save.
- **on_level_ready.** With a pending restore: moves the player to `respawn_id`'s marker (no
  marker → it stays at the scene's Player node), `apply_character_state(character)`, puts
  `level_exempt` into the controller while no progression component exists, applies the death
  floor after a death, and refreshes `character` from the player. A New Game keeps the scene's
  Player position, sets `respawn_id` to the level's start checkpoint (the root's
  `start_checkpoint`, else the level record's) and commits the first checkpoint. A level with
  checkpoints and no session document (a test level in the sandbox) commits a `level_start`
  checkpoint. `growth_changed` events raised while restoring are ignored.
- **Stats** survive death reloads (deaths, loads, play time while checkpoints are on); Continue
  takes them from the save.

### Command line (after `--`)

| Option | Effect |
| --- | --- |
| (none) | `title` (the play link opens the title screen) |
| `--autoplay=S`, `--scenario=X`, `--level=…` without `--mode` | `sandbox` (the M1 tools keep working) |
| `--new-game` / `--continue` without `--mode` | `valley` |
| `--mode=title\|sandbox\|valley` | that mode; an unknown mode shows the title |
| `--mode=valley` | `--continue`: load the save (its own level); `--new-game`: a new game; neither: continue when a save loads, else a new game; no Valley and no usable save: the title |
| `--level=res://….tscn` | load this scene instead of the mode's level |
| `--save-dir=user://…` | slot folder (`<dir>/valley_1.json`); keeps saving on with `--no-user-settings` |
| `--no-user-settings` | `persist = false` (no writes, Continue off) unless `--save-dir` is given |


- `read()`: SaveIO's main-then-backup read; a newer-version main is copied to
  `valley_1.schemaN.rejected.json` (message "… It was kept as valley_1.schema2.rejected.json."),
  and SaveIO never makes it the backup. A main file with a valid envelope but invalid content
  also falls back to the backup ("valley_1.json is invalid (…). Recovered the previous valid copy
  from valley_1.json.bak."). Unknown abilities, weapons, the ancestry and inventory items are
  dropped and named ("Dropped ids this build does not know: …").
- Document (`schema_version` 1): `build_version`, `saved_at_unix`, `slot`, `level`
  (`level.valley`, or a scene path for a `--level` run), `checkpoint {respawn, reason}`,
  `character`, `world` (WorldState v2), `stats`. Reasons: `new_game`, `level_start`,
  `waystone`, `shrine_reached`, `shrine_activated`, `shrine_rested`, `shrine_screen`, `growth`,
  `boss_defeated`, `quest_stage`.

## Decisions and deviations

1. **System doc name.** `docs/systems/P06.md` (task, §1.1 item 5); §3.6 names
   `P06-session-saves.md`.
2. **Only the Valley writes the slot.** §3.6 says nothing is written unless
   `checkpoints_enabled() and persist`; writes additionally need `is_valley()`. A test level
   played in the sandbox mode (for example `--level=res://scenes/test/flow_test_level.tscn`)
   keeps its checkpoints in memory and can never overwrite the player's one slot. The Valley
   flow on a test level (`--mode=valley --level=…`, the tests) writes as the Valley does.
3. **Pending-request merge.** "Later requests replace earlier ones": the reason is replaced, the
   respawn only when the later request names one.
4. **Shrine ids.** `shrine_activated` / `shrine_rested` carry a `shrine_id` whose kind the plan
   leaves open; both world ids (checkpoint ids) and record ids resolve (§ Public APIs), and an
   unresolvable id leaves the respawn unchanged instead of storing a bogus one. P06 never
   references P05's `Shrine`: it uses the group `shrines` and the `shrine_id` / `world_id`
   properties.
5. **Growth from a shrine** is a `growth_changed` for the player with a shrine within 25 m.
   A debug grow (F6/F7) away from every shrine takes no checkpoint; events raised during a
   restore (P05's `apply_state`) are ignored.
6. **New Game's first checkpoint** is committed in the first `on_level_ready` (player at the
   scene's Player node, respawn = the start checkpoint), so the document exists before any death.
   A test level started in the sandbox commits a `level_start` checkpoint the same way.
7. **The death floor is applied after `apply_character_state`**: it is a fraction of maxima
   that only exist once growth and attributes are applied.
8. **`level_exempt`** is put into the controller by GameSession while no progression component
   exists (GiantPlayer is P05's file in this wave; P12's component will own it).
9. **Continue needs the save's level, not the Valley.** New Game is disabled without the Valley
   as planned, but a save made on a scene of its own (the flow test level) can be continued from
   the title or with `--mode=valley --continue`; a Valley save still needs `level.valley`.
10. **Mode defaults.** `--level` without `--mode` boots the sandbox mode on that level;
    `--new-game` / `--continue` without `--mode` mean the Valley; `--mode=valley` alone
    continues when a save loads, else starts a new game.
11. **The loading frame pauses the tree**, so no simulation tick runs without the level and the
    seeded soak keeps its exact timeline (identical gameplay counters). The autopilot is created
    after the level, as before.
12. **Death confirm in `_input`, with pad A.** The input router turns pad A into a (dead) jump
    and marks it handled, so the confirm runs in `main._input`; the HUD hint reads "Enter / A"
    in both modes (the sandbox text changed from "Press Enter to restart the sandbox").
13. **Resets by mode.** Where checkpoints exist, a reset reason ending in `after_death` (Enter,
    the autopilot) reloads the checkpoint; the Valley ignores other sandbox resets (F5 shows a
    hint). Everything else is the M1 reset, now through `GameSession.restart_sandbox()`, which
    also forgets a test level's in-memory checkpoints.
14. **Extra files**: `scripts/world/flow_test_level.gd` (the test level's root needs a script
    to set `test_checkpoints`) and `tests/support/fake_shrine.gd` (a stand-in for P05's Shrine).
15. **API additions** beyond §2.9: `take_checkpoint(reason, respawn := "")` (the shrine screen
    names its shrine), `change_mode`, `last_mode_result`, `restart_sandbox`, `apply_args`,
    `parse_args`, `valley_available`, `save_level_available`, `scene_for_level`,
    `current_level_id`, `has_checkpoint`, `pending_checkpoint`, `player()`, `find_checkpoint`,
    `place_player`, `apply_reload_floor`, `death_reload_floor`, `shrine_respawn`,
    `nearest_shrine`, and the test hooks `allow_scene_reload` / `scene_reloads`;
    `SaveSlots.rejected_path`, `SaveSlots.sanitize`, `delete_slot(include_rejected)`;
    `CharacterState.full_resources` and `sanitize`. The §2.9 signatures are kept
    (`start_new_valley()` stays `void`; results go through `change_mode`).
16. **New Game asks before replacing a saved game** (a second press confirms). Not in the plan;
    one slot makes an accidental overwrite expensive.
17. **Toast texts** are short enough for the 340 px region; the full write error goes to a HUD
    message.
