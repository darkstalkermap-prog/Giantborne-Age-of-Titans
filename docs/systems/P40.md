## The world tour (`tools/world_tour.gd`, `tools/world_tour.sh`)

A tool like M5's `tools/valley_tour.gd`, for the world. It runs a world bot's campaign in a 1280 x 720 window
(Xvfb when no display is set) and takes a screenshot as the bot reaches each place: the Kingsgate shelf's view
first, then the settlements, formations, engines, bosses, the map and the end screen. It prints `TOUR_SHOT`,
`TOUR_PROGRESS`, `TOUR_ENDING` and `TOUR_END` lines and writes `shots.jsonl`. With `--tour-places=<names>` it makes
scripted placements instead of a bot run (`PLACES` in the script: `drowned_steps`, `shelf`, `map`), for the places a
route does not pass. The wrapper takes `--out`, `--run` (a world spec of `tools/run_bots.sh`; the default is
`w.order_crown:novice:1:assist`), `--places`, `--render` and extra arguments after `--`. README §6 has the command.

- **Rendering:** drawing every frame under llvmpipe cost about 5-6 s a frame (35 frames in 205 s), so a whole
  campaign would have taken days. The tool turns rendering on only for each shot's two frames, so the bot plays at
  its headless speed. This is plan §6.3's headless fallback in one process. `--render=always` draws every frame.
- **Two fixes the run found in the tool, before its commit:** `_finish` quit at once when the campaign flag ended
  the run, so the autopilot never printed `AUTOPILOT_RESULT`; it now hands back and waits up to 600 frames (checked
  by a scratch run that sets `campaign.completed` midway: `AUTOPILOT_RESULT` completed, 0 errors, exit 0). The map
  shot now zooms out (`set_zoom(0)`).
- **No game code changed** for the tour, and no test was added: it is a capture tool, as `valley_tour.gd` is. Its
  script passes `tools/gd.sh --headless --check-only --script tools/world_tour.gd`, and the wrapper passes `bash -n`.

**The run** (2026-11-14, 02:49-03:37 UTC, on `f904d68`, the final game code with the version):

- **The command:** `tools/world_tour.sh --out=<dir>`. It runs `xvfb-run -a -s "-screen 0 1280x720x24" tools/gd.sh
  --path . --resolution 1280x720 --audio-driver Dummy --fixed-fps 60 -s res://tools/world_tour.gd --
  --no-user-settings --save-dir=user://world_tour_saves/<name> --mode=world --new-game --deterministic-streaming
  --tour-dir=<dir> --bot-preset=peaceful --bot-oaths=crown:breach,wood:slay --scenario=world --autoplay=7200
  --bot-skill=novice --bot-seed=1 --bot-assist`.
- **The bot:** the crown-first order (the peaceful preset with the oaths `crown:breach` and `wood:slay`), novice,
  seed 1, assisted.
- **The rendering:** Xvfb 1280 x 720 x 24, software OpenGL (Mesa 25.2.8 llvmpipe, OpenGL 4.5 core, Godot 4.6.3's
  Compatibility renderer), the default preset (`medium`, from `--no-user-settings`). Shots took 437 s of the 2,849 s
  of wall time (a median of 0.86 s a shot); the run played at 0.62 x real time.
- **How far it got:** stage 3 at the start; stage 4 at 78.3 s; the crown's breach of Fort Aldmere, the Iron
  Regiment broken and Corvane spared; stage 5 at 746.9 s; the Troll Matriarch slain for the wood's oath (1,095 s);
  stage 6 at 1,639.8 s; the Moot at 1,704 s; Harrok beaten and spared; **the Stone Throne claimed** at level 17. The
  end screen reads 29:22.
- **Simulated time, deaths, shots:** 1,762.18 s to the campaign's end, **0 deaths**, 140 shots. No game error and
  no invariant failure; the only warning was Godot's V-Sync driver warning at start.
- **Not the gate's run:** the rendered run does not replay the gate's headless crown-first order (1,975.87 s, 0
  deaths). The bot closes a pausing screen after 0.25 s of real time, so a rendered run's timing parts from a
  headless one.
- **The placed runs**, with the committed tool: the Drowned Steps (4 shots; the crown-first route never enters
  them), the map on the bot run's final save (2 shots, `--places=map -- --continue`), and the shelf's view retaken
  from the bot's own spot and camera angle without the first tutorial tip (1 shot).

**The shots:** every shot was looked at (contact sheets, then the candidates at full size). Twelve were kept, 9 the
bot's and 3 placed, as JPG at quality 85 (58-128 KB each). They are `docs/screenshots/11_kingsgate_shelf.jpg` to
`22_end_screen.jpg` and the README's gallery rows after the Valley's: the Kingsgate shelf first, Brannock at stage 4,
a pike formation under its banner, the Moot battery's engines, the Greywood, the Drowned Steps, Fort Aldmere's gate,
the Iron Regiment's battle, the Moot, the Stone Throne, the map and the end screen.

**What the shots show that no headless run had** (all cosmetic, none fixed in this release: FOLLOWUPS, "From the
ship package (P40)"; handoff §8):

## Decisions and deviations

- **The world tour renders only its shots' frames** (above). Plan §6.3 asks for screenshots "beside the bot" and
  allows a headless fallback; a fully rendered campaign under llvmpipe would take days.
- **The tour's route is the crown-first order, assisted.** It is the one route that breaches Fort Aldmere, fights
  the Iron Regiment and passes Brannock at stage 4; none of the three presets takes the crown at its default two
  oaths. Three places it does not show well are placed shots from the same tool.
- **The version commit also changes `config/description`'s milestone count**, because `test_launcher_notes`
  requires the version's milestone there. Both are metadata: the version is shown on the title and pause screens and
  written into saves, and nothing in the game reads the description.
- **The two web checks the build run ran under load were run again on the quiet machine**, and their verdicts are
  the quiet runs'. The loaded runs stay in `docs/PERFORMANCE.md` beside them.
- **The director's counted combatants (the FOLLOWUPS row "The director's counted combatants pass the budget of
  12"): P40 keeps the director's rule, with no code change.**
  - **What `python3 tools/bot_report.py <batch> world_streaming` reads on the final code** (the M9 gate's 17 world
    runs, `final_after_world_a`, `_assisted`, `_orders`, `_stability_a`, `_extra_campaign` and `_extra_orders`, and
    the release's two quiet bot runs): the count passed 12 in 4 of 19 runs.
    - 16 for 43.88 s in `w_mixed_expert_1`;
    - 16 for 0.28 s in `w_conqueror_expert_1`;
    - 16 for 0.18 s in `w_conqueror_novice_1_assist` (the gate's record does not list this run);
    - 13 for 0.05 s in the 60-minute run.
    - The other 15 runs stayed at 12, among them `w24perf_mixed` and `w24perf_crown`.
  - **No counted member spawned at the cap:** the bot's budget invariant held in every run. Each excess is a
    faction's members already in the world when it turned hostile, so it is bounded by that faction (at most 16).
  - **The cost the row named does not come from the excess.** The Aldmere March's CPU per tick over 8 ms is there
    with no excess: the war camp's sabotage alone on a quiet machine reads 9.98 ms p95 in the region with never
    more than 12 counted (`w24perf_mixed`). Holding the newly hostile members back would not bring it under 8 ms.
    It would also leave armed members of a hostile faction standing idle in sight of the giant: a new behaviour, to
    be tuned and played, and too late for this release.
  - **What follows:** the rule stays as P17b wrote it. The budget's row reads it as a measured exceedance
    (handoff §5.6). The FOLLOWUPS row is closed as decided, with M10 free to reopen it if the reference PC finds a
    cost in the 43.9 s case (DECISIONS.md decision 45).
- **Process:** the tour's long run was relaunched detached once (the two-hour limit on background commands), and a
  few-second `--check-only` parse once overlapped it.
