# P14 — Stress route, performance capture and graphics presets

Wave 7, lane B (beside P11b). Branch `pkg/P14`. Plan: `docs/plans/M2_M5_PLAN.md` §3.16, with §5.3
(the stress route), §5.4 (budgets and web mitigations), §2.8.3 (`status.debug_invulnerable`, the
`level` record's `render` and `web_overrides`), §1.5 (hotspots: `autopilot.gd`, `level_root.gd`,
`encounter_director.gd`, `settings.gd`, `settings_pages.gd`, `level_valley.json`) and spec §16.
No follow-up in `docs/plans/FOLLOWUPS.md` was assigned to this package.

## What was built

- **Graphics presets.** `Settings.graphics_quality` (`low` | `medium`; `medium` by default on
  desktop, always `low` on the web; the command-line flag `--graphics=low|medium` fixes it for one
  run without saving it) and a "Graphics preset" row on the Settings page (disabled, with the
  reason, on the web or under the flag). `LevelRoot` applies its level record's `render` preset for
  it at load and on every change of the setting: the Sun's shadow distance (0 switches the shadows
  off), `visibility_range_end` on the level's scenery (groups `scenery` and `valley_scenery`) and
  the viewport's MSAA (put back when the level leaves). On the web (`LevelRoot.force_web_for_tests`
  in tests) the record's `web_overrides` force `low` and start AI tier 1 at 30 m (the director's
  `near_m`).
- **PerfProbe** (`scripts/debug/perf_probe.gd`): per tick the whole physics tick timed from inside
  (`cpu_tick_ms`, the "Sim CPU per tick"), `Sim.step` alone, active combatants and debris; per frame
  the idle callbacks, the real frame delta (N/A under `--fixed-fps`), GPU and CPU render time (N/A
  headless), draw calls, objects, primitives, nodes and static memory; `PERF_RESULT {json}` with
  nearest-rank p50 / p95 / p99, min, max, mean, the five slowest ticks, per-section summaries and
  the §5.4 budget verdicts.
- **The stress route** (spec §16): `scenes/test/stress_arena.tscn` (`tools/builders/stress.gd`) and
  its record `level.stress_arena`; `StressScenario` (`scripts/debug/stress_scenario.gd`) keeps 12
  combatants active (respawn 5 s after a death or rout), tracks the 20 breakables and puts fresh
  copies in place of broken ones after each lap, and runs the bot.
- **The Valley walk** (`scripts/debug/valley_walk.gd`): the AI LOD tier comparison (tier 2 / 1 / 0,
  CPU per tick always, draw calls when rendered) from the Cradle, then a stage-1 walk through every
  district with the director running (teleporting the legs behind gates).
- **Autopilot dispatch**: `--scenario=stress`, `--scenario=valley_walk` (each adds a PerfProbe),
  `--perf` (a probe for any other run), `--stress-stage=N`, `--walk-teleport`; the scenario's report
  in `AUTOPILOT_RESULT` ("stress" / "valley_walk", "perf", "scenario_failures", "scenario_ok") and
  exit code 2 when a scenario's own check fails (errors still exit 1).
- **`status.debug_invulnerable`** (`damage_taken_mult` 0, hidden): the stress bot and the Valley walk
  give it to the player; nothing in normal play does.
- **`docs/PERFORMANCE.md`**: the budget table with the container's verdicts, the tools, the
  commands (container and reference PC), the container results, the owner's blank reference-PC
  table, the findings and the web build checklist.

## Public APIs

### Settings (`scripts/core/settings.gd`, autoload)

```gdscript
const GRAPHICS_QUALITIES := ["low", "medium"]; const GRAPHICS_DEFAULT := "medium"
const GRAPHICS_WEB := "low"; const GRAPHICS_ARG := "--graphics="

static func parse_graphics_arg(args: PackedStringArray) -> Dictionary   # {"value", "error"}

```

The saved setting is `values.graphics_quality` (`DEFAULTS` and `ENUMS` carry it). An unknown
`--graphics` value warns and is ignored.

### SettingsPages (`ui/screens/settings_pages.gd`)

`static func graphics_row(grid) -> OptionButton`: "Graphics preset" (Low / Medium) in the Settings
page, before "Motion blur"; disabled, showing the preset in effect with the reason as its tooltip,
on the web or under `--graphics`.

### LevelRoot (`scripts/world/level_root.gd`)

```gdscript
const SCENERY_GROUPS := ["scenery", "valley_scenery"]

```

`apply_graphics` sets the Sun's `directional_shadow_max_distance` (a distance of 0 switches its
shadows off; a sun the scene built without shadows never gets them), `visibility_range_end` of the
scenery below this root and the viewport's `msaa_3d` (restored in `_exit_tree`); on the web it also
sets the director's `near_m` to `web_overrides.ai_tier1_m` (at most `mid_m`). The director reads its
LOD distances from the record in its own `_ready`, before the level's, so the override wins; a test
that calls `reload_encounters()` afterwards calls `apply_graphics()` again.

## The AI LOD and budget tuning pass

Measured, then nothing changed: `encounter_director.gd` keeps its constants and
`level_valley.json` its `lod` (near 40 m, mid 90 m, 30-tick check, corpses freed after 6 s), budget
(12), `render` and `web_overrides` values.

- **Budget 12**: twelve engaged combatants at full AI rate with debris at its cap run at
  4.88 ms p95 per tick in the container (budget 8 ms).
- **Tiers** (the Valley walk's comparison, 12 distant members, headless): tier 2 1.54 ms mean per tick,
  tier 1 3.03, tier 0 2.79; draw calls (Xvfb) 595 / 849 / 846. Tier 2 (dormant, proxy) saves about
  1.3 ms and 251 draw calls; tier 1 saves nothing measurable for idle members (they still move and
  collide every tick) and engaged members always run tier 0, so moving the tier-0/1 boundary (or the
  web's 30 m) changes little. A nearer tier 2 on the web would save more but needs a new
  `web_overrides` field (a schema change outside P14): recommended to P17b / P18.
- **The Valley walk** (stage 1, director running) stays at 3.37 ms p95 per tick; its slowest ticks
  are encounter activations (13-25 ms) and the first load of an enemy scene (387 ms for four kinds at
  once): a spawn-time problem, not an LOD one (see the known gaps).

## Decisions and deviations

1. **Doc name** `docs/systems/P14.md` (the task and §1.1 item 5); §3.16 names
   `P14-stress-perf.md`.
2. **CPU per tick is timed from inside the physics step**, not read from
   `Performance.TIME_PHYSICS_PROCESS` / `TIME_PROCESS` as §3.16 item 3 says: Godot 4.6 refreshes those
   monitors once per second of wall time with the largest value of that second (600 headless frames
   in the container gave one refresh), so per-tick percentiles of them would repeat a few maxima. The
   probe reports their largest values as `engine_physics_max_ms` / `engine_process_max_ms`.
3. **`--fixed-fps` is detected** from the frame deltas (all identical): the engine consumes the flag
   and keeps it out of `OS.get_cmdline_args()`.
4. **The stress arena has its own level record**, `data/world/level_stress_arena.json` (not in the
   owned paths), so `--graphics=low` applies there exactly as in the Valley (same presets).
5. **Its combatants are spawned by `StressScenario`, not by the EncounterDirector**: the director never
   brings a killed member back, and its file is "tuning constants only" for P14. The arena has no
   director, so every combatant runs AI tier 0 (the worst case). A **routed** combatant counts as down
   too (out of the fight) and is replaced 5 s later, like a dead one.
6. **The breakables come back after every lap** (fresh copies with world ids `<original>.r<n>`, so
   WorldState sees new props): the plan's 300 s loop needs something to break after the first lap.
   Their loot and XP are given again (stress only).
7. **The stress bot grows the giant to stage 2** (`--stress-stage=N` changes it): the size of the
   courtyard fights and the wider 9 m camera. At stage 1 a lap takes longer than the smoke test's
   60 s (a 60 s run broke 16 of the 20); stage 3 laps in about 37 s on this branch, but under P11b's
   awe (a giant at least 4x a unit's height) its soldiers would rout on sight. At stage 2 the
   soldiers are outmatched (they hold formation), wolves harass, archers spread, the mage kites,
   ogres engage.
8. **"Heavy and Footfall on every breakable"** is read as the bot's breaking attacks: Footfall on a
   cluster, a heavy per breakable, and a light only when a light finishes it or stamina is short.
   Crates and weakened pines often fall to the Footfall itself.
9. **Clustered breakables.** The 20 breakables sit in clusters at six of the eight stops; each of the
   two dense corners (2 crates, 2 pines, 2 fences) breaks into exactly 40 debris pieces, so the pool
   saturates at its cap of 40 (spread evenly along the route it peaked at 22).
10. **The Valley walk also carries `status.debug_invulnerable`** (the plan names it for the stress run):
    the encounters it passes engage it and a death would end the capture. Nothing in normal play
    applies it.
11. **The LOD comparison runs first, from the Cradle**, where every encounter is dormant and beyond
    90 m, and compares tiers 2, 1 and 0 (CPU per tick always, draw calls when rendered); the plan asked
    for the tier-2 draw-call difference only.
12. **A preset `shadow_distance_m` of 0 switches the sun's shadows off** (`LevelRoot`), a data knob for
    the draw-call finding below. No preset uses it: the plan's low preset (60 m) is kept.
13. **Scenery groups**: `LevelRoot` applies the scenery range to group `scenery` (new, any level) and to
    P10b's `valley_scenery` (`tools/builders/valley.gd` is not P14's to edit).
14. **MSAA is put back** when a level leaves the tree, so the title and the sandbox keep the project's
    default after a Valley session at `low`.
15. **Extra options**: `--perf` (a probe for any autoplay run), `--stress-stage=N`, `--walk-teleport`.
16. **No tuning constant changed** (`encounter_director.gd` and `level_valley.json` are untouched): the
    measurements below support the current values.

## Known gaps

- Reference-PC frame times and GPU times: **NOT RUN** (owner; commands in `docs/PERFORMANCE.md`).
  The container has no GPU: its render times are software rendering (llvmpipe) and only its draw-call
  counts carry over to real hardware.
- The web build: **NOT RUN** (P18; checklist in `docs/PERFORMANCE.md`).
- **Draw calls exceed the 250 budget** in the Valley and the stress arena (findings in
  `docs/PERFORMANCE.md`); the fixes belong to the builders (props) and the presets (P15, P17b, P18).
- **Encounter spawn hitch** (a 13-25 ms tick per activation, about 100-150 ms when an archetype's
  scene loads for the first time): measured and reported, not fixed (the director's spawning is
  outside P14's "tuning constants only").
- The stress bot is a load generator, not a player: it does not block, dodge, lock on or use the
  other abilities.
- The Valley walk does not enter the boss arena (its gate would close behind the giant).
- Container CPU numbers come from a debug build on a shared 4-core container: indicative only.
