## What was built

- **Six abilities and four statuses** (data, §4.7): Sweeping Blow, Stone Skin, Runic Bolt,
  Ancestral Mend, Thunder Roar and the ultimate Titan Surge, with `status.stone_skin`,
  `status.slow`, `status.mend` and `status.titan_surge`. Heavy Footfall gains
  `radius_by_stage_m: [3, 4, 5]`. The sandbox giant has all seven abilities slotted plus the
  ultimate; `progression.default` lists them.
- **Action schema fields** (anchor P03): `sector_deg`, `radius_from`, `radius_by_stage_m`,
  `self_statuses`, `on_hit_statuses`, `morale_damage` and the `projectile` block, with their
  semantic checks.
- **Projectiles.** `Projectile` (pure state and ballistics) and `ProjectileSystem` (one per level,
  a Sim POST_ACTORS hook at order 100): exact constant-gravity kinematics per tick, a sphere cast
  against the world (WORLD | BREAKABLE) that stops the shot, a swept sphere against hurtboxes
  (`HitQueryAdapter.sweep_sphere`), hits queued through `HitFactory` with the impact point as
  `attacker_position`, `from_projectile` and the projectile id as pulse id, the impact splash, pooled
  meshes per visual kind, the events `projectile_spawned` / `projectile_impact`, and removal at range,
  on impact, after 5 s, below the world or when the owner is freed.
- **AttackRunner shapes** (anchor P03): `sector_pulse`, `projectile`, the `self_statuses` of any
  action (applied when it enters ACTIVE, so `hit_shape: none` buffs work), the pulse radius rules
  (`radius_from: melee_reach`, `radius_by_stage_m`), `area_effect` on every cylinder pulse, sector
  pulse and splash, `aim_point`, and `Events.ability_effect` emits.
- **HitFactory and AttackContext** (anchor P03): live outgoing multipliers for melee and pulses, frozen
  ones for projectiles; `on_hit_statuses`, `morale_damage`, weapon tags on weapon blows, the
  projectile fields, `area_effect`, and `skip_candidate` (the player's area effects skip entities the
  player may not target).
- **Hostile-only targeting** (decision 17): lock-on candidates and soft targeting use
  `TargetingRules.player_may_target`. Direct weapon arcs and direct projectile hits are never
  filtered.
- **Player aim.** `PlayerAttack` resolves the launch point (`launch_offset_m × k`) and the aim
  (locked target's anchor, else the point under the crosshair).
- **Presentation.** ActorRig poses for sector sweeps, one-hand casts, two-hand throws, roars and
  self buffs, a `pose_override` rig-state key, status tints, and the anchors P05/P07/P08.
  HitFeedback: the sector fan, the roar ring, a rising ring for self buffs, sparks for casts and
  impacts, green heal numbers, status tints, and the `aim_preview` landing ring that P07 emits.
- **HUD.** Hotbar reasons come from `CombatController.preview_reason` (one code path with the
  controller); projectile slots show a target line; notices for essence, fury, level and target
  rejections; the F1 help lists the loadout's abilities; the status row widget
  (`ui/hud/status_row.gd`).
- **Screens.** `UiScreen` and `ScreenStack` (§2.10.2). The pause menu is a `UiScreen`; its
  Settings and Controls pages moved to `SettingsPages` for reuse by the title screen (P06).
  `main.gd` builds the stack; Esc / Start, focus loss and a lost pointer lock go through it.

### ProjectileSystem (`scripts/world/projectile_system.gd`, group `projectile_system`)

```gdscript
signal projectile_moved(projectile: Projectile)
signal projectile_ended(projectile: Projectile, reason: String)  # impact|range|timeout|fell|owner_gone|cleared
const GROUP := "projectile_system"; const HOOK_ORDER := 100; const SPLASH_PULSE_OFFSET := 1000000
static func instance(tree: SceneTree) -> ProjectileSystem   # lazily created under parent_for(tree)

func spawn(owner: CombatEntity, a: ActionDef, origin: Vector3, velocity: Vector3, ctx: AttackContext) -> int
func active_count() -> int; func projectiles() -> Array[Projectile]; func get_projectile(id) -> Projectile
func clear() -> void                       # removes every projectile without impacts (tests, tools)
func debug_lines() -> PackedStringArray    # group debug_info_providers
## @anchor P07   ## @anchor P09            # at the end of the file
```

- `spawn` snapshots `ctx` (`AttackContext.snapshot()`), gives it the projectile's registry,
  `from_projectile = true`, `projectile_id`, and freezes the owner's outgoing multipliers (a bolt
  keeps the Titan Surge it was fired with).
- A projectile first moves on the tick after its launch. Each tick: `next_position`, a sphere cast
  to the first world contact, `sweep_sphere` from the start to that point, candidates sorted by
  `HitFactory.sort_candidates`. A non-piercing shot ends at the first sub-step that queued a hit
  (every target touched at that sub-step is hit); `pierce` keeps flying. One hit per target per
  projectile. A dead target's hurtbox neither stops nor absorbs a shot.
- **Splash** (`impact_radius_m > 0`): a cylinder pulse of `impact_radius_m × impact_height_m`
  centred on the impact point, line of sight from that point, pulse id `id + SPLASH_PULSE_OFFSET`,
  `area_effect = true`, built from the same action, so it carries its `category`, tags and
  `on_hit_statuses`. Entities hit directly are skipped. It also emits `area_pulse`.
- A dead owner's shots keep flying and still land (decision 8; Sim keeps them unless the owner
  died on that tick). A freed owner (despawned, unloaded) removes them (`owner_gone`).

### Screens

```gdscript
class_name UiScreen extends Control
signal closed(result: Dictionary)
var stack: ScreenStack; var args: Dictionary; var screen_name := ""
func pauses_game() -> bool (true); func first_focus() -> Control (null)
func on_open() -> void; func on_close() -> void
func cancel() -> void                     # default close({"cancelled": true})
func close(result: Dictionary = {}) -> void; func is_open() -> bool

class_name ScreenStack extends Control    # group "screen_stack", PROCESS_MODE_ALWAYS
const SCREENS := {...}                    # all eight planned paths; missing files open nothing
const HOTKEYS := {"inventory": "inventory"}
func open(screen_name: String, args: Dictionary = {}) -> UiScreen   # null: unknown or not built yet
func push(screen: UiScreen) -> void; func pop(screen: UiScreen, result: Dictionary = {}) -> void
func top() -> UiScreen; func is_open(screen_name) -> bool; func any_open() -> bool
func has_screen(screen) -> bool; func count() -> int
func open_seconds() -> float              # real seconds since the open pausing screens paused the game
func handle_cancel() -> bool              # cancels the top screen
func handle_pause() -> void               # cancel the top screen, else open "pause"
func close_all() -> void
static func close_all_static() -> int     # every stack in the tree; the count it closed (reset hook)
```

- UiScreen defaults (PROCESS_MODE_ALWAYS, full rect, MOUSE_FILTER_STOP) are set when it first enters
  the tree, so subclasses need no `super()`.
- `push` adds the screen as the top child, runs `on_open`, then focuses the top screen's
  `first_focus()`. `pop` runs `on_close`, emits `closed(result)` and frees the screen; the focus
  goes back to the new top screen.
- While any screen is open: InputRouter context MENU and a visible mouse. While a pausing screen is
  open: the tree is paused. When the last screen closes: unpaused, GAMEPLAY, the mouse is captured
  again (never headless; on the web only when the closing input was a click).
- Input (`_unhandled_input`): `pause` → `handle_pause()`; while a screen is open `ui_cancel` (pad
  B) cancels the top screen; with none open a `HOTKEYS` action opens its screen.
  `Events.ui_screen_requested(screen, args)` opens deferred.
- A stack that leaves the tree (scene reload) unpauses and restores GAMEPLAY if it had set them.
- **PauseMenu** (`ui/pause_menu.gd`, `extends UiScreen`): the same Main / Settings / Controls pages.
  `first_focus()` is Resume. `on_open` shows `Settings.load_message`; `on_close` cancels a rebind
  capture and flushes settings. Inside a stack `open()` does nothing, `close()` pops it and
  `is_open()` asks the stack; used on its own it pauses and resumes the game itself, as in M1.
  `current_page()`, `settings_pages()`.
- **SettingsPages** (`ui/screens/settings_pages.gd`, RefCounted, one per screen):
  `build_settings()`, `build_controls()`, static `slider_row` / `check_row` / `option_row`,
  `refresh_bindings()`, `is_capturing()`, `capture_text()`, `begin_capture(action, pad)`,
  `cancel_capture()`, `handle_input(event) -> bool` (the screen forwards `_input` while capturing).
- `main.gd`: `screen_stack` replaces the `pause_menu` field. `_unhandled_input` routes `pause`
  through `screen_stack.handle_pause()` and ignores the other global keys while a screen is open;
  focus loss and (web) a lost pointer lock call `screen_stack.open("pause")`; a sandbox reset
  closes every screen first. `static func is_capture_click` is unchanged.

## Decisions and deviations

1. **Doc name.** This file is `docs/systems/P03.md` (plan §1.1 item 5 and the task); §3.3's owned
   paths name `P03-abilities.md`.
2. **Target line glyph.** The plan shows `→ Soldier`. Godot's default font has no U+2192 glyph
   (`ThemeDB.fallback_font.has_char(0x2192)` is false on 4.6.3), so the line reads `» Soldier`
   (U+00BB is present). The label clips with an ellipsis.
3. **Projectile meshes live in ProjectileSystem** (design item 2: pooled meshes per visual kind),
   not in HitFeedback, which draws the casts and impacts. `thrown_body` has no mesh (P07 moves the
   body).
4. **Timings and details the plan leaves open:** Sweeping Blow 0.30 / 0.10 / 0.40 s, tags
   `Ability, AoE, Unparryable`, not crit-eligible, knockback impulse 4 (at most 8 m/s); Stone Skin
   0.20 / 0.05 / 0.30 s; Mend 0.30 / 0.05 / 0.35 s; Roar 0.40 / 0.10 / 0.40 s and pulse height
   4 m; Titan Surge 0.30 / 0.05 / 0.30 s with no cooldown (the 100-fury cost gates it). Sweeping
   Blow, the self buffs and the roar use `soft_target_max_deg: 0`, so they never turn the giant.
5. **Sector membership** is the yaw of the hurtbox centre seen from the actor's feet, so a large
   body straddling the edge counts by its centre. The pulse's height is the action's `height_m`
   when set, otherwise the actor's height.
6. **`sweep_sphere` occlusion** tests the line from the sphere's centre to the hurtbox centre only.
   `sweep_capsule`'s first leg (attack origin to weapon point) has no counterpart: the sphere cast
   already stops the projectile at the first world contact, and the sweep only covers the path up
   to it.
7. **A non-piercing projectile hits every target touched at its first hit sub-step**, then ends.
   Corpses are skipped (a dead target's hurtbox would otherwise absorb the shot with an ignored
   hit).
8. **Launch and first move.** A projectile launches on the action's first ACTIVE tick and first
   moves on the next tick, whether or not the system already existed (a hook added during a step
   first runs on the next tick).
9. **Player aim modes.** Besides `lock_or_camera`, the player supports `camera`, `forward` and
   `target` (the runner's stored `aim_point`, else as `lock_or_camera`). Enemies (`default_launch`)
   treat the player-only modes as `target`, whose fallback without a brain target is the nearest
   living entity they may damage.
10. **The roar is a cylinder pulse with morale damage**, not a separate shape. It still emits
    `area_pulse` (for cosmetic props, P08); HitFeedback skips its Footfall ring and draws the roar
    ring from `ability_effect` "roar" instead.
11. **Self statuses** are applied on `phase_entered` ACTIVE whatever the hit shape, with the actor as
    source; a status that is refused (immunity) emits no `self_buff`.
12. **MENU context for every modal screen.** ScreenStack sets the MENU input context and frees the
    mouse while any screen is open, pausing or not (the title screen needs menu input too); only
    pausing screens pause the tree. Added `handle_pause()`, `has_screen()` and `count()`; pad B
    (`ui_cancel`) cancels the top screen. Closed screens are freed.
13. **Hostile-only targeting** was switched in `PlayerTargeting.may_target()`, the one-line switch
    point P02 built for it, rather than below the P03 anchor; nothing is added below that anchor.
14. **Hotbar parameters from components.** The plan has the HUD call `preview_reason`; to keep it
    one code path once P07 adds the grab precheck, any player component may add request
    parameters through `preview_params(slot_key, def, params)`. The HUD also shows the notices
    GiantPlayer does not (essence, fury, level, no target).
15. **Status tints are event driven** (`status_applied` / `status_expired`). `StatusSet.remove()`
    and `clear()` emit neither, so a status removed that way would keep its tint until the next
    status event on that actor; nothing in the slice removes statuses outside a scene reload.
16. **`aim_preview` ring.** P07 emits `ability_effect` "aim_preview" during Boulder Hurl's windup
    and has no hotspot edit in `hit_feedback.gd`, so P03 draws the ring now.
