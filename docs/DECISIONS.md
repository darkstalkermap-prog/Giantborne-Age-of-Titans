# Implementation decisions and spec interpretations

The specification ([GIANTBORN_SPEC_V2.md](GIANTBORN_SPEC_V2.md)) asks that any interpretation or
conflict resolution be recorded. Everything below is a proposed default for M0/M1; all of it is
data or a small code path that can be changed.

## Engine and project

| Decision | Why |
| --- | --- |
| **Godot 4.6.3-stable (official build `7d41c59c4`)**, GDScript, Compatibility renderer | Latest patch of the previous stable line (4.7.2 was newest on 2026-11-04). The spec asks for a pinned stable version, not the newest. |
| Jolt Physics selected explicitly in `project.godot` | Godot's recommended 3D engine in 4.6; Area3D shape queries were probed and work. |
| Fixed 60 Hz simulation in the `Sim` autoload | All combat runs in whole ticks; rendering (camera, animation, UI) runs in `_process`. |
| Physics interpolation **off** | Bodies move at 60 Hz. On displays above 60 Hz, bodies update at 60 Hz while the camera's mouse look stays per-frame. Physics interpolation is a later improvement. |
| Input bindings live in `data/input/default_bindings.json`, not `project.godot` | Keeps every binding remappable and data-driven; user overrides are saved in `user://settings.json`. |
| Scenes are generated by `tools/build_scenes.tscn` | Valid, editor-friendly `.tscn` files from code. **The generated scenes are the source of truth once you start editing them in the editor; re-running the tool overwrites them.** |
| Reset (debug F5, "Restart sandbox", restart after death) reloads the scene | The most reliable way to restore every system. World deltas are cleared on these resets, because the sandbox is a sandbox. |

## Combat rules

| Topic | Decision |
| --- | --- |
| Timing | Seconds convert to ticks once (`round(s * 60)`). An action accepted at tick T is at elapsed 0; light attacks are active from elapsed 12 to 20 and finish at 39 (0.65 s). Dodge invulnerability covers elapsed 6 to 17 (0.10 s up to, not including, 0.30 s). |
| Parry window | A hit is a parry when `block_elapsed_ticks < 12` (the first 0.20 s), counting from the tick block was accepted. |
| Tapped block | A block press lasts at least the parry window (0.20 s), even if released earlier, so a tap gives a full parry window. Holding never reopens the window; a new press (and a new 5 stamina) is needed. |
| Failed parry | A parryable hit that lands inside the window but cannot be parried (for example, under 5 stamina) is resolved as an ordinary block **and consumes the window**, so a later hit cannot become a free parry. Successful parries do not consume the window, and each costs its own 5 stamina. Unparryable hits blocked inside the window do not consume it. |
| Guard break | "Apply 50% of that damage" means 50% of the pre-block mitigated damage. Remaining stamina is consumed, then a 1.0 s stagger. |
| Blocked hits and poise | A successful block applies no poise damage to the blocker; stamina is the guard meter. |
| Parry poise | The parry's 40 poise damage to the attacker is not size-scaled. |
| Stagger immunity | The 1.5 s post-stagger immunity applies after any stagger (poise break or guard break), to prevent stun-locks. Poise damage is also ignored while staggered. |
| Interrupt policy | Each action record carries `interrupt_policy` (`hard_stagger` by default; `super_armor` is supported but unused in M1). Interrupted actions are never refunded. |
| Cancel windows | Light attacks may cancel their recovery into the next light, dodge or block. Heavy attacks may only dodge-cancel, from 0.25 s into recovery (never during the active strike; the validator rejects such data). Dodge may cancel into attacks/block/dodge from 0.15 s into its recovery. |
| Input buffer | Requests blocked only by state or timing are queued (one slot, newest wins) and stay live for 9 ticks (0.15 s), then are revalidated. Requests that fail on resources, cooldown, locks or empty slots are rejected immediately with a reason and spend nothing. |
| Combo chain | The next chained light is used if requested during the current light's recovery or within 0.35 s after it ends. After light 3 the chain restarts. Heavy, abilities and interruptions break the chain. |
| Sprint | Sprint drains 8 stamina/s and needs movement. On reaching zero it stays locked until the key is released or stamina reaches 25 (prevents flicker). Shift + light issues one heavy and stops sprint; sprint resumes after recovery if Shift is still held and the giant is moving. Toggle mode cancels when movement stops. |
| Stamina regeneration | 15/s after 1.0 s since the last spend. The delay keeps counting while regeneration is paused (sprint, block, attack/cast). |
| Fury | +4 the first time a basic attack instance deals damage to a fury-granting target (crowd hits award 4 once), +6 per parry, +8 per kill. Training dummy: grants fury. Fence/props: never grant fury. Heavy Footfall: an ability, not a basic attack, so it grants no fury. "Out of combat" means 10 s without dealing or taking a resolved hit. |
| Crits | 5% for the player, rolled from the seeded `Sim.rng` in stable hit order. Enemies have 0%. |
| Same-tick deaths | Hits resolve in a stable order (attacker id, attack instance, pulse, sweep sub-step, distance, target id). If an attacker dies earlier in the same resolution pass, its remaining in-flight hits are dropped. |
| Dead targets | Resolve as `IGNORED`: no damage, no events, no fury, no resources. |
| Practice dummy | Armor 25, so on-screen numbers reproduce the worked example (light 37, heavy 66, Footfall 44). Unkillable (health floors at 1) and refills 3 s after the last hit. Lockable as a practice target. |
| Soldier | Health 220, armor 15, poise threshold 40 (a parry's 40 poise always staggers it). Slash: P=30, 0.55 s windup. Overhead chop: P=45, 0.85 s windup. Both are parryable and tracked only during the first 60% / 50% of the windup. |

## Hit detection

| Topic | Decision |
| --- | --- |
| Weapon shape | A capsule along the arm and club, from 1.5 m to 3.35 m out of the right-shoulder pivot, radius 0.45 m: about 3.5 m reach from the actor's center, matching `melee_reach_m`. The procedural arm animation reads the same `AttackGeometry` functions, so the visible swing is the swing that is tested. |
| Sweeps | Previous-to-current pose, sub-stepped at no more than 3/4 of the radius per step (up to 16 sub-steps per tick). |
| Occlusion | For each overlapped hurtbox, the line from the attack origin to the weapon point, and from the weapon point to the hurtbox, must be clear of world and breakable geometry. The target's own colliders are excluded, so the fence can still be hit. |
| Query buffer | Starts at 64 results and doubles until nothing is cut off (hard cap 4096, with a warning), so there are no silent caps. |
| Hurtboxes | Area3D volumes on their own layer; they never block movement or attacks. Dedup is per entity id. |

## Camera and targeting

| Topic | Decision |
| --- | --- |
| Third-person framing | Stage 1 shoulder offset is 1.1 m and default pitch is −18°, so small enemies in front of the giant stay visible. |
| Lock-on framing | Aims at the torso anchor, with pitch clamped to −35°..+8° (never steeply up). For targets shorter than 70% of the giant and closer than about 12 m, the camera orbits up to 32° to the shoulder side and may look down to −48°, so the giant's body does not hide the target. While locked in third person, movement is relative to the target (forward walks toward it). |
| Aim and cone | Lock cone and Q alignment use horizontal (yaw-only) directions, so a giant looking down still locks nearby humans. Visibility is a ray from the giant's eyes. |
| Wheel | While locked, the wheel switches targets; otherwise it zooms the third-person camera between `camera_zoom_min_m` and `camera_zoom_max_m`. |
| First person | Eye at 92% of height, 0.18 m ahead. Head meshes sit on render layer 2, which the first-person camera culls (they still cast shadows). The real arm and club meshes are the hand/weapon representation. First-person lock never rotates the camera unless the optional aim assist is on (≤ 20°/s within 25°). |
| Motion blur | No motion blur exists in the prototype; the setting is shown disabled ("Off"). |

## AI, world and data

| Topic | Decision |
| --- | --- |
| Perception | 5 Hz with per-actor phase offsets; 25 m sight, 75° half-angle cone (360° within 8 m once aware); 15 m hearing of the player's attacks; being hit reveals the attacker. |
| Engage distance | Soldiers stand about 1.85 m from the giant's center and attack within about 2.05 m. They approach from the side they are already on, toward the legs. |
| Path failure | No progress (< 0.3 m) for 2 s triggers `on_path_failed`: next patrol point, or reposition to the other side. Soldiers never teleport. Without navmesh data (for example, the test worlds), soldiers steer directly. |
| Navigation | The sandbox bakes its navmesh at load. When the fence breaks, it re-bakes in the background, since that is cheap at 120 m. Larger worlds should use authored alternate paths or obstacle toggles, as the spec asks. |
| Morale | Implemented minimally: 70 at start, −10 per nearby allied death, flee below 25 and regroup above 45. With one soldier it never triggers in M1. |
| Breakables | Health is not persisted mid-damage; only the destroyed state, damage stage and loot flag are. The blocking shape is freed (not just disabled), so navmesh re-bakes ignore it. |
| World deltas | Kept in memory in M1. The versioned format (`WorldState.to_save_dict`) and `SaveIO` are ready for the M3/M4 checkpoint saves. |
| Data validation | Unknown keys are errors, which catches typos. Timings that are not whole ticks produce warnings and are rounded. Any validation error replaces the sandbox with a full error list. |
| Settings file | Saved through `SaveIO` (temp file → verify → backup the previous valid file → replace). Corrupt files fall back to the backup with a message in the pause menu. A newer schema version is rejected; the file is kept as `settings.schemaN.rejected.json`, and defaults are used. |
